# 可确认的连续语音面试模式设计

- 状态：待复审
- 日期：2026-08-15
- 设计基线：`e74d54e2b0c5b625a976a267942275fd1140bfea`
- 分支：`feat/20260815-continuous-voice-interview`
- 本文范围：第五期产品与技术设计；本提交不包含实施计划或产品代码

## 1. 背景

OfferPilot 的语音面试已经完成四期能力：

1. 浏览器题目朗读、录音、回放、本地识别、文字校对与显式确认；
2. 用户主动下载的离线 Whisper 转写，以及浏览器识别和手工输入降级；
3. 本地 VAD、临时字幕、停顿与语速复盘；
4. 用户二次确认的表达快照、成长趋势和定向复练入口。

沉浸式 Interview Studio 又补齐了真实投递与快速练习、逐轮追问、证据展示和全屏交互。当前缺口不再是某项单独的语音技术，而是每一轮仍需要用户在朗读、录音、停止、转写和下一题之间反复操作。第五期把既有能力组合成用户主动开启的“连续语音模式”，减少机械点击，同时继续保留人工确认、证据门控和本地音频边界。

## 2. 方案选择

### 2.1 采用：可确认的连续语音面试

系统在用户主动开启后，顺序执行题目朗读、等待开口、本地录音、回答结束检测、最终转写和确认。只有用户确认文字后，才沿用现有 Mock Interview API 提交回答、生成证据化追问并朗读下一题。

这一方案复用现有浏览器 TTS、MediaRecorder、VAD、离线 Whisper、Studio Attempt/Turn 和结果未知恢复，不引入新的云端语音服务，也不改变回答确认语义。

### 2.2 不采用：仅增加面试官角色或题型

HR 面、技术面、行为面等内容模式可以后续单独设计，但它们不会解决现有语音操作割裂的问题。第五期不扩大题型和人格设定范围。

### 2.3 不采用：云端实时 Speech-to-Speech Agent

云端实时语音会引入音频上传、持续连接、额外费用、延迟、Provider 兼容和隐私授权，并会使现有“确认文字后提交”的边界变得模糊。第五期不使用云端 STT、TTS、语音克隆、声纹或实时音频 Agent。

## 3. 目标与非目标

### 3.1 目标

- 在 Interview Studio 中提供“标准模式 / 连续语音模式”切换。
- 用户只需在会话开始时主动授权连续语音；每轮题目可自动朗读并在朗读结束后进入等待开口。
- 发声后由本地 VAD 检测可能结束点，自动停止本地录音并进入转写，但绝不自动提交回答。
- 用户可编辑、继续补充、重新录制或确认最终文字。
- 确认后复用现有回答提交、证据化追问、幂等键、lease/CAS、结果未知和历史只读语义。
- 任一语音能力失败时都能回到标准文本或手动语音流程，不中断 Attempt。
- 保持原始音频、PCM、VAD 帧和临时字幕不离开浏览器、不写入数据库。

### 3.2 非目标

- 不支持唤醒词、后台监听、摄像头、情绪识别、口型同步或说话人识别。
- 不允许用语音命令替代最终确认，也不自动点击“确认回答”。
- 不支持用户打断系统朗读后自动识别为回答；第五期不做 barge-in。
- 不新增云端 STT/TTS 配置或 Provider 路由。
- 不自动保存表达成长快照，不自动写入 Story、Knowledge、Memory、Application 或 Offer。
- 不改变最多五轮、用户可提前结束及反馈 Proposal 的既有规则。

## 4. 用户流程

### 4.1 开启

Studio 顶部增加模式切换。用户选择“连续语音模式”后进入一次性预检：

1. 解释题目会由系统音色朗读、麦克风只在回答阶段启用、音频不会上传；
2. 检测 TTS、MediaRecorder、本地转写和麦克风能力；
3. 用户点击“开始连续语音面试”后才请求麦克风权限；
4. 权限成功后进入第一轮，失败则显示具体原因并保留标准模式。

模式偏好可以保存在本地，但麦克风授权和自动监听不能因历史偏好而自行启动。每次重新进入 Studio 都必须由用户操作开启。

### 4.2 单轮闭环

```text
朗读当前题目
→ 等待用户开口
→ 本地录音与临时字幕
→ 检测可能回答结束
→ 本地最终转写
→ 用户编辑、补充、重录或确认
→ 提交已确认文字
→ 生成证据化追问
→ 朗读下一题
```

题目朗读过程中不启用回答录音。用户可以点击“跳过朗读，开始回答”；这属于明确操作，不实现自动插话检测。

### 4.3 回答结束检测

- 尚未检测到发声时，静音不会结束回答；页面持续显示“等待开口”。
- 检测到发声后，连续静音达到平衡模式阈值时进入三秒结束倒计时。
- 倒计时期间用户再次发声则取消结束并继续录音。
- 倒计时结束只停止本地录音并开始转写，不提交任何业务请求。
- 用户可在确认前点击“继续补充”，新增本地音频片段并重新生成完整转写。
- 单轮录音仍受既有五分钟上限约束；达到上限时停止录音并进入转写确认。

第五期只提供“平衡”阈值，不暴露毫秒级参数。后续只有真实使用证明需要时，才考虑“更灵敏 / 更宽松”等预设。

### 4.4 确认与下一题

转写完成后必须停在确认界面。用户确认的字符串是唯一可进入现有回答 API 的内容。提交成功后：

- 当前 Turn 冻结；
- 可选表达复盘在本地生成，但不阻塞下一题；
- 使用原 Attempt 和新一轮幂等键生成下一题；
- 下一题响应通过既有结构化证据校验后，才进入朗读；
- 202、网络未知或 Provider 未知继续使用原 key 恢复，不新建 Attempt。

## 5. 状态机

新增纯前端 `ContinuousVoiceSessionController`，只编排既有能力，不直接访问网络或媒体 API。建议状态如下：

```text
disabled
→ preflight
→ reading_question
→ waiting_for_speech
→ listening
→ end_candidate
→ transcribing
→ reviewing_transcript
→ submitting_confirmed_answer
→ generating_next_question
→ reading_question
```

终止或分支状态：

- `paused`：页面隐藏、用户暂停或系统需要停止捕获；
- `fallback_standard`：某项语音能力不可继续，但 Attempt 和当前文字保留；
- `result_unknown`：业务请求结果未知，冻结输入并保留原 key；
- `completed`：达到轮次上限或用户在已确认回答后结束；
- `closed`：资源清理完成。

状态机必须拒绝非法跳转。例如 `transcribing` 不能直接进入 `submitting_confirmed_answer`，必须先进入 `reviewing_transcript` 并收到显式确认事件。

## 6. 组件与职责

### 6.1 `ContinuousVoiceModePanel`

- 展示预检、当前阶段、主要操作和降级说明；
- 不持有 MediaStream、Worker 或业务请求；
- 只向控制器发送用户事件。

### 6.2 `ContinuousVoiceSessionController`

- 管理代次、状态跳转和每轮资源所有权；
- 串联题目朗读、捕获运行时、转写协调器与 Studio 回调；
- 通过 generation/session token 丢弃迟到的 TTS、VAD、转写和请求结果；
- 退出、切换模式、页面隐藏和组件卸载时执行幂等清理。

### 6.3 既有 `VoiceAnswerComposer`

- 继续拥有录音、回放、临时字幕、最终转写和文字编辑；
- 增加受控的连续模式意图，而不是复制第二套录音实现；
- 标准模式行为保持不变。

### 6.4 既有 `InterviewStudio`

- 继续拥有 Attempt、Turn、回答提交、下一题、反馈和证据栏；
- 只接收已经确认的回答文字；
- 连续模式不绕过现有 `canSubmit`、结果未知、退出确认或证据展示。

## 7. 媒体与隐私生命周期

- 麦克风只能在用户开启连续模式且当前状态允许回答时启用。
- 题目朗读、Provider 请求、转写确认和下一题生成期间必须停止或禁用捕获。
- 每轮结束、退出 Studio、切换标准模式、页面隐藏、设备变化或错误时停止所有音轨。
- AudioContext、AudioWorklet、Analyser、MediaRecorder、Object URL、Worker 和定时器均由当前 session generation 持有并在 `finally` 清理。
- 原始音频、PCM、VAD 帧、临时字幕和浏览器语音列表不得进入 API、日志、诊断报告、localStorage、IndexedDB 或数据库。
- 离线 Whisper 模型文件继续按二期规则保存在浏览器缓存；它不是用户音频。
- 未确认文字只存在于当前挂载会话。关闭或刷新前必须提示，不能静默持久化。

## 8. TTS、转写与降级顺序

### 8.1 题目朗读

- 继续使用浏览器 `speechSynthesis` 和系统音色；
- 支持暂停、继续、跳过和重新朗读；
- 朗读失败时显示文字题目并转入手动开始回答；
- 不下载或调用云端 TTS。

### 8.2 转写

沿用既有三层降级：

1. 已下载且可用的离线 Whisper；
2. 支持本地处理的浏览器识别；
3. 手工输入。

临时字幕只帮助用户观察当前识别状态，最终确认必须基于完整录音的最终转写或手工编辑。离线模型未下载时，连续模式不得自动触发网络下载。

### 8.3 整体降级

- TTS 不可用：保留连续录音流程，题目改为阅读；
- 麦克风拒绝或 MediaRecorder 不可用：回到标准文本模式；
- VAD/Worklet 不可用：保留手动停止录音；
- 最终转写失败：保留回放与手工输入；
- 下一题生成未知：冻结已确认回答，使用原 key 恢复；
- 页面隐藏：立即暂停或停止采集，恢复页面后必须由用户继续。

任一降级都不得删除已成功的 Turn、重建 Attempt 或重复调用 Provider。

## 9. Haru 与反馈

Haru 继续只表达可观察的运行状态：

- 正在朗读；
- 等待开口；
- 正在倾听；
- 检测到可能结束；
- 正在本地转写；
- 等待用户确认；
- 正在准备追问；
- 已降级到标准模式。

Haru 不显示或朗读未经确认的转写内容，不主动弹出 Pilot，不替用户确认回答。Studio 安全区、拖动和隐藏行为沿用现有实现。

## 10. 可访问性与交互

- 连续模式开关使用可感知的选中状态，并关联隐私说明。
- 状态变化通过克制的 `aria-live` 播报，避免临时字幕逐字打断读屏。
- 所有关键动作可通过键盘完成：开启、跳过朗读、暂停、继续、结束、补充、重录、编辑、确认和退出。
- 麦克风活动必须同时有文字和图标提示，不能仅依赖颜色或 Haru 动画。
- `prefers-reduced-motion` 下取消脉冲和装饰动画，不影响录音、转写和确认。
- 窄屏保持单一主滚动；固定回答区、证据抽屉和 Haru 不得遮挡确认操作。

## 11. 数据、API 与兼容性

第五期原则上不新增数据库迁移、公开 API 或后端领域模型：

- 回答继续写入既有 Mock Interview Turn；
- 下一题继续使用既有结构化问题与 evidence refs；
- 表达快照继续使用第四期 API，并保持二次确认；
- 连续模式偏好只保存在本地，不写入服务端；
- 历史记录只保存既有已确认文字和快照，不保存“连续模式”推断标签。

如果实施时发现现有接口无法安全恢复原 Attempt/key，应先回到设计复审，不得为了连续体验增加自动重试或隐式写入。

## 12. 错误处理与并发边界

- 每个媒体异步操作、转写任务和业务请求都绑定 session generation。
- 用户切换模式、退出或开始新一轮后，旧 generation 的迟到结果只能清理资源，不能更新 UI 或提交数据。
- React StrictMode 重挂载不得创建两个捕获运行时或重复请求下一题。
- TTS `onend/onerror`、VAD 倒计时、转写完成和用户手动操作同时发生时，只允许一个状态跳转获胜。
- 已确认回答提交成功但响应丢失时，继续使用现有历史回读和原 key 对账；不得再次确认或重复 Provider 调用。
- 关闭 Studio 时，已确认 Turn 保留；未确认音频和文字按用户确认丢弃；结果未知恢复信息保持现有边界。

## 13. 测试设计

### 13.1 纯函数和状态机

- 所有合法状态跳转和非法跳转拒绝；
- 朗读完成、跳过朗读、等待开口、发声、静音倒计时、再次发声取消倒计时；
- 五分钟上限、手工停止、继续补充和重新录制；
- 转写完成必须进入确认，不能自动提交；
- generation 变化后丢弃迟到回调；
- 每种能力缺失的确定性降级。

### 13.2 媒体生命周期

- 麦克风只在允许状态启用；
- TTS 与录音不同时运行；
- 页面隐藏、切换模式、退出、错误和卸载均停止音轨、Worklet、Worker 与定时器；
- StrictMode、pending `getUserMedia`、deferred runtime 和转写竞态；
- 原始音频、PCM 和临时字幕零请求、零持久化、零日志。

### 13.3 Studio 集成

- 真实投递与快速练习都可开启连续模式；
- 已确认文字只提交一次并自动进入证据化追问；
- 202、网络未知、Provider 未知使用原 key 恢复；
- 退出确认、历史只读、来源变化和最多五轮保持不变；
- 表达快照保存失败不阻塞下一题，也不自动保存。

### 13.4 浏览器验收

使用亮色中文候选人“筱哲”，在隔离数据与可审计 Provider 下完成：

```text
开启连续语音
→ 朗读首题
→ Mock PCM 发声与自然停顿
→ 最终转写
→ 编辑并确认
→ 自动生成并朗读证据化追问
→ 继续补充一次回答
→ 完成五轮并生成复盘
```

同时验收麦克风拒绝、无 TTS、无 VAD、离线模型未下载、转写失败、页面隐藏、Escape 退出和结果未知恢复。截图至少覆盖 `1440×900` 与 `390×844`，并确认无横向溢出、固定回答区遮挡或 Haru 碰撞。

浏览器审计必须证明：媒体阶段零业务请求；只有用户确认文字后才出现回答提交；浏览器外部请求为零，除非用户在设置中主动下载离线模型。

## 14. 发布门禁

- 状态机、媒体生命周期、Studio 集成和安全负向测试通过；
- 前端完整分组门禁、TypeScript 和生产构建通过；
- 受影响的后端 Mock Interview、Smoke、Ruff、Mypy 和分组门禁通过；
- 本地 verify、real-AI API verify 与隔离浏览器验收按现有发布规则执行；
- 独立代码复审无未处理 P0/P1/P2；
- `git diff --check`、文件范围与工作区清洁度通过；
- 发布报告明确区分 Mock PCM、真实麦克风、受控 Provider 和真实 Provider 证据。

## 15. 破坏性变化与后续扩展

预期无破坏性变化。标准文字模式、手动语音模式、离线 Whisper、表达复盘、成长档案、Interview Studio、Haru、Mock Interview API 和历史数据全部保留。

多面试官、面试形式、云端实时语音、语音克隆、口型同步、唤醒词和真正免确认的全自动对话均不属于第五期。任何后续扩展都不得反向削弱本期的主动开启、本地音频和人工确认不变量。
