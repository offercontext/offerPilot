# ADR-0016：隔离且有界的陪伴日常

- Status: Accepted
- 日期：2026-10-21
- Decider：用户确认陪伴 V1 方案并授权分支实施
- 依据：[Haru 单一工作 owner](../../superpowers/specs/2026-08-23-haru-surface-completion-design.md)、[主动队列](0012-bound-local-proactive-jobs.md)、[Knowledge 边界](../knowledge-system.md)

## Context

Pilot 与 Haru 是同一个助手的不同入口。陪伴需要一点连续的小日常，但不能产生第二个工作
Agent、真实外部行为、用户事实污染、重复通知，或要求用户照料角色的负担。

## Decision

版本化 persona 保持无忧、自然呆萌和玩心，不指定儿童年龄，也不以成熟、坚强、爱好效率作为
成长目标。被委托的工作依旧认真可靠，缺信息会问，结果依赖证据；求职权限与确认语义不变。

日常由确定性的有限模板组成：同时至多一项活动和一个轻量愿望。角色可独立开始/推进自己的
虚拟步骤，也可以闲着。状态、事件和真实参与各有明确来源；独立活动不会写入投递、面试或
已确认用户记忆。愿望不等于执行，执行不等于真实结果，不连接视频、聊天、浏览器或语音服务。

活动仅在打开应用、结束聊天、完成工作或明确互动时最多前进一步，不建立常驻模型循环，
多日离线也不会补写多天故事。暂停不推进；明确约定一起做的节点持续等待，打开界面不是参与。
工作展示临时覆盖生活展示，不删除活动。状态写入使用 workspace identity、revision CAS 和
command receipt；重试不能重复推进，重置更换 identity，拒绝旧窗口命令。
V1.1 在同一 Pilot owner 的确定性入口接受明确的自然语言加入、等待、暂停、恢复及约定步骤的
真实回复，活动卡仍可使用。采用完整句式，不凭关键词；否定、引用、假设、转述、无目标的
“继续/好了”、不支持的表达和混合工作请求均不触发生活状态写入。普通模型生成没有写权限。
这是明确用户指令对应活动控件的入口，不是新增模型写工具，不改变既有求职工具 HITL。

接纳 turn 时冻结当前 identity、revision、activity_id、共享步骤及解析结果；执行时从实际 user
message 再验证，并复用原执行 owner 的 handler/commit 围栏与 companion CAS、幂等回执。
冻结后换活动、暂停、重置或关闭不能把旧句子套用到新状态。同步、SSE 与 detached Runtime
共用此入口；发生冲突说明未修改，不自动重绑重试。状态提交后回复交付失败不回滚、不重复执行。

“等我回来一起选颜色”保存一个明确等待步骤；上线、时间经过、模型回复都不能完成它。
同一对话中等待选色时，“蓝色”才是一条有目标的真实选择；名称使用“叫……吧”等明确句式。
记录只证明该虚拟共享选择，不证明现实行为、整项活动完成或用户长期偏好。来源为实际用户
message/conversation/turn ID；原文仍在聊天内，生活记录只保存有界选择值。没有开放式 planner、
任意自由文本约定提取或多步骤计划。跨对话或已插入其他话题后的无目标短回复不会自动消费旧约定；重新明确参与后才接收短答。

删除来源对话同时擦除其派生选择与参与证据；被撤去来源的当前等待转为暂停，不自动继续。
删除后的控件回执保留请求身份与 digest，但历史响应替换为当前脱敏快照，不能重放被删约定，
也不能因删除而重新执行旧命令。跨对话恢复所引用的约定也会从其幂等回复缓存中脱敏；引用依赖
不等于来源所有权，删除恢复所在对话不删除另一对话的原始参与来源。清除生活数据也擦除聊天派生生活记录，保留原聊天本身。新增 schema 为可重复执行的增量迁移，
旧活动、身份和控件记录保留；persona 升级提高 revision 使旧发送候选失效。

人格、当前生活、带来源的事件和真实共同经历是四个逻辑类别。对话只在 workspace 的明确
生活话题中取有界当前片段，使用标明 companion_life 的数据信封、身份与版本，而不是授权或
用户长期偏好。复用 current_scope 的原子预算与来源指纹，不改变 manifest 或业务工具表面。

主动消息复用 ProactiveJob 的队列、认领、期限、发布围栏与安静时段。companion_life 的
application_id=0 是内部隔离标识，不是投递来源；不显示在求职任务 Inbox，不消耗求职提醒预算。
独立进度先提交，消息后入队；通知失败不回滚或再次推进。后台调度不派发日常消息，只有可见
客户端请求交付。发布重读来源、presence、设置和预算；旧 revision 候选不能发布。丢失响应
不重放，宁可少一句也不重复打扰。

所有仍有效窗口的输入、工作、待确认、模拟面试、安静或失败标记合并后保守抑制发送。可见工作界面正在
处理失败时不转移注意力；历史 failed 记录不等于永久未读失败，未决 result_unknown 继续阻止主动发送。关闭桌面聊天输入前也保守抑制日常，不增加桌面执行 owner。presence
60 秒过期，客户端递增序号防止乱序心跳清掉新状态，过期仍保留高水位直到重置。连续
30 分钟无可见使用后开始新会话，隐藏窗口心跳不延长会话。明确的“这次安静陪伴”保存
在使用会话中，刷新、关闭原窗口和重置生活数据都不撤销；只由明确取消或新会话清除。

默认每个本地活跃日最多两条纯生活主动消息，less 最多一条，间隔至少一小时；同时保留滚动
24 小时上限防止更换时区绕过，时间规则沿用主动设置的 IANA 时区。未回应一次主动邀请后，
当前使用会话不再发；只在生活互动中确认回应，普通打开应用不是回应。用户主动互动不受发送
预算限制。零条也正常，不补发积压。

关闭陪伴保留私有状态但停止生活推进与展示，不影响求职功能；关闭主动性仅禁止主动消息，
不抹掉兴趣和活动。关闭陪伴仍报告无内容的可见使用状态，不能通过开关重置使用会话的静默或
未回应限制。隐藏状态只改变展示。清除生活数据删除日常、事件、共同参与和回执并更换
身份；无内容的用量信息和已消耗通知额度保留至原窗口结束，避免重置绕过防打扰限制。

## Consequences

生活可以连续而无需模型持续运行；跨窗口、重试和离线恢复可验证。其代价是模板能力有限，
不等价于真实世界经历，断网交付可能保守丢弃；不会为了补偿消息失败而改变生活事实。
既有记忆、权限、作业和确认体系仍为唯一业务执行路径，无破坏性数据迁移。

## Alternatives Considered

1. 第二个自治 Agent 与独立通知系统：会重复 owner、权限和竞态处理，V1 不采用。
2. 把虚拟经历写入普通已确认记忆：混淆用户事实与角色创作，因此隔离持久化和来源。
3. 新增全套上下文 contributor/manifest 版本：当前只需明确的 workspace 生活片段，现有
   current_scope 已能保留身份、版本、原子信封和预算，因此不扩大共享协议。

## V1.2 连续性与表达

新活动先自己开始，不在创建时自动发出愿望；纸小船实际推进到第二步时可以有一个命名愿望，
纸星星在第三步可以有一个挑选愿望，云朵这类活动可以完全没有邀请。愿望与该次已提交的
进展共用事件和 revision，不单独推进或扩大发送额度。活动内只提供一次；拒绝、接受、真实
参与和旧版本活动使用持久的无内容标记防止再次邀请。删除来源聊天不恢复已用掉的邀请机会，
但仍删除其选择、约定和参与事实。旧活动保留未处理愿望，启动补标与 persona 升级合并一次
revision 更新，重复启动无额外变化；不回溯生成遗失的愿望。

Web 与桌面镜像按当前模板、已到达步骤、状态和稳定 activity ID 选择小量自然说法；刷新、
设置修改和时钟变化不制造新进展或随机改口。等待使用保存的真实约定，暂停不描述后续推进；
完成、放下和暂无安排允许安静休息。未知模板或无效步骤保守降级，不描述未发生的步骤。
这仍是有限虚拟活动，不是看过真实视频、执行外部工具或产生真实世界成果的履历。

明确生活问题可只读取一条最近的真实共享选择，跨活动后标为 prior_activity，不把上一次的
颜色或名字套到当前活动，也不推断用户偏好。读取同时验证 participation、identity、activity、
实际 user message、conversation 和 turn 的精确对应；原来源删除后不再可见，重置身份不能
读回旧记录。模糊的“我们的约定呢？”只在同一对话紧邻当前活动的真实共享指令时解析为
生活回指；插入工作/其他话题或换对话后保守不读取。这是只读来源，不重新打开短答写入槽。
当前片段仍优先，一条可选历史回忆如超出 2 KiB 信封预算会整体省略，不截断当前约定。

边界：中文自然语言写入仍限 V1.1 明确完整句式，无法理解的自由表达交给普通对话澄清而不写。
本轮没有新增开放式 planner、用户画像提取、真实外部活动或无限故事生成。真实模型是否把
这些有来源的片段表达得足够自然仍需后续实际使用反馈；测试中的模型桩不证明模型效果。

## V1.3 实体回忆与撤回一个共同步骤

“我们的小船叫什么”“还记得我们一起折的小船吗”等关系明确的问题按结构化模板类型和
activity ID 读取实际选择，不再以全局最新选择代替指定对象。纸小船、纸星星和云朵仍是仅有的
有限虚拟对象。同类对象有多次时要求澄清；明确“上次/最近一起做的”才选择最近对应活动，
“这次/现在的”不回退到旧活动。一次问多个对象保守澄清，不把不同对象的细节混成一项。
名称与颜色问题只读匹配步骤的选择，来源不可用时如实说明。类型是虚拟元数据，真实选择仍
必须通过原 participation、identity、activity、user message、conversation、turn 源链检查。

0036 给事件增量增加可空 template_id。新事件保存类型；升级只从当前生活权威状态回填
同一 identity/activity 的空绑定，旧的非当前故事不会靠文字猜类型，冲突绑定不会覆盖或读取。
persona 升级和当前绑定补齐合并一次 revision 围栏，重复启动不变。指定旧对象时不夹带另一
当前活动或参与内容；有歧义时不提供任选的历史选择。仍为只读有界信封，不延长短答写入窗口，
删除来源或重置身份后不能靠回忆读回已删内容。

“这步你自己做吧”是撤回当前约定的一步，不是完成、删除历史、暂停或放弃整项活动。
仅当前 promised 参与改为 abandoned，清除本步用户标记、等待与愿望，保留既有 completed
选择、活动 ID、模板和步骤。原本暂停的活动仍暂停；独立活动在下一次真实 wake 且满足
原最小间隔后才继续，不把长时间等待算作已经做过的工作。该撤回事件不产生主动邀请，
活动的已邀请标记保留，没有追问或情感负担。

自然撤回仍经原 Pilot owner、turn 冻结、activity/participation/revision 校验和幂等回执。
“这步”等指代要求同一来源对话紧邻真实共享/暂停/恢复指令；明确当前对象的完整撤回句可在
该来源对话恢复目标。跨对话、控件建立的共享步骤、引用/否定/假设/转述/问句、工作或其他
混合请求不写生活状态，保留原文给正常对话处理。活动详情提供“这步请 Haru 自己做”作为
明确操作入口。撤回不会重新解释先前事实；删除来源时仍清除派生参与和旧回执。

本轮的确定性验证覆盖来源与状态边界，不证明真实模型人格或一周自然交流效果。未增加模型
费用、外部执行权限、常驻循环或新的代理；未支持的自由表达应澄清，不假装执行。

## V1.4–V1.5 模型表达事实边界

模型读取的当前步骤使用一基序号与明确的最后一步标记，存储/UI 的零基索引不变；步骤标题
不是完成证明。同类对象有多个候选与一次提到多种对象分别解释，但都不证明用户一起制作。
用户用“我们”称呼、角色独立进度和一次有来源的命名不能扩大为共同完成整项活动。来源缺失
仅代表当前无法核验，不等于从未发生。仍沿用原子 2 KiB 信封，优先保留当前状态与实际参与。

工作总结格式仅适用于需要结论与后续行动的工作任务。闲聊不复述内部字段或来源规则，直接
问到能力时简短真实地回答，区分真实外部行动与可独立继续的虚拟小步骤；复杂/工作请求不受
闲聊篇幅限制。所有安全和事实约束保留，不用固定回复替换模型输出。

两次真实小样本中，第二次改善了工作格式外溢、额外步骤和指定对象回忆，但仍有无来源共同
动作与机械边界解释，整体体验未通过。V1.5 仅做免费输入/回归修正，尚未经新的真实语气复验；
机制测试和提示词检查不能证明体验已达标。原一次纠正批次已消耗，不因剩余预算启用第三批。

## 自定义人设 V1（2026-10-31）

用户确认支持同一个伙伴的可编辑人设，保留官方默认、预设草稿、表达预览和恢复上一版；
不增加多角色、角色市场、自动人格进化或新的外部能力。Pilot 保留工作入口名称，OfferPilot
保留产品名称；伙伴称呼默认为 Haru，可在同一工作台两入口共用。

人设是独立单工作台 profile，不复用或重置生活 identity。内容仅包括有界名字、性格标签、
说话习惯、表达详略、兴趣、明确虚构的背景、补充表达说明，以及现有三个活动模板的白名单。
未知字段、超长内容及不安全控制字符拒绝保存；这些字段不是工具权限、系统指令或用户事实。
`enabled/proactivity/hide_status`、主动消息频率、预算及求职确认设置仍沿用原有独立配置。

当前指针引用追加式 revision；更新与恢复均需确认、expected_revision CAS 和 command_id
幂等回执。恢复旧内容会创建新 revision，不删除历史，也不重置记忆、生活状态或共同承诺。
API 收敛为 `GET /api/companion/persona`、`GET /api/companion/persona/revisions` 和
`POST /api/companion/persona/mutations`（update / restore）。三个预设仅载入前端草稿，
取消不写入；预览是明确标注的静态表达示例，不调用模型，不证明实际模型效果。

新 turn 在接纳事务中把 profile_id、revision、内容 hash 写入已有
`pilot_turns.source_versions_json`。同一运行的排队、流式、确认、重试和恢复读取对应不可变
版本，不能以 active 指针变化替换它。无绑定的历史运行使用显式官方默认兼容，不默读 latest。
冻结的仅是可编辑表达数据；当前核心规则、权限与来源漂移检查照常应用，不能恢复旧安全策略
或因风格变化自动重新执行。模型可见投影保留语义字段和非授权／虚构说明，机器 ID 与 hash
只用于来源元数据，不作为角色台词。官方默认表达（包括仅修改活动白名单、恢复官方默认）
不重复注入人设包，仍校验冻结的 profile/revision/hash，并使用当前程序管理的默认表达规则；
默认模型消息和预算与原 v1.6 保持一致，不因开放设置而增加 token。自定义表达包存在时，
完整 `current_scope` 与人设共同计入必需原子预算；放不下则拒绝继续，不静默挤掉生活或业务
事实。无此表达包的调用保留原预算策略。

兴趣文字仅影响交流，不映射为新能力。白名单仅筛选下一项新活动，空集保持闲着；进行中或
共同等待的旧活动继续按完整内置模板注册表解析，保存不是撤回、完成、取消承诺或重置。
现有陪伴主动文案来自已持久化的确定性事实模板，不读取人设；现有面试草稿也使用独立工作
模板，因此保存人设不取消这些任务、不重新生成或退还预算。以后若增加人设派生的待发表达，
须在发表时增加表达版本围栏，仍不能借此重放业务或退还已使用预算。

人设来源不写 confirmed memory、聊天事实、参与证据或工具授权配置。确认、执行身份与预算
由现有程序路径约束；不编造事实和自然表达等仍包含 prompt 层约束，字段白名单不等于完全
防住 prompt injection。离线与假模型测试不能代替真实模型质量评估；后者需另行费用授权。

## 整合候选验收边界（2026-11-01）

本次将上述陪伴与自定义人设叠加到当前主线；普通附件或图片参与的请求不冻结纯文本生活
指令，仍走原资料／图片能力和确认边界。新设置不影响图片输入、历史图片、原工作 owner。

真实表达审查区分意图、明确承诺和已完成事实：条件句或愿望不能单独证明动作已完成；
明确“答应”可以支持存在承诺，不支持履约。用户自述、角色虚构背景和虚拟活动进度分别保持
原事实域，不升级为用户确认事实或现实共同经历。来源不充分可保留不确定，不等同于矛盾。
