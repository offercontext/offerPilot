# Harness P2：持久任务与增量时间线实施计划

> 状态：已实施并完成针对性验证。范围为交付路线图 §7；P3–P5 独立实施。
> 基线：`602238c2`，包含已审阅的 P0、P1 及展示恢复修复。

**目标：**同一次客户端提交在响应丢失、重复发送、进程重启后仍指向同一任务；读取展示只使用持久事实，不能重新执行模型、工具或审批。

**边界：**保留当前断连取消和 HITL。P2 不承诺后台执行存活，不引入 P3 generation/fencing。工作区以已认证进程的数据目录为边界，不接受客户端声明租户。历史对话保留现有读取兼容。

## 1. 原子接纳与任务标识

- 在 `models.py` 新增独立 Pilot Turn、请求接纳记录。业务库持久化，Journal 关闭不影响。
- 新增 `pilot_timeline` repository：SQLite 写事务内校验已有请求、创建或加载 Conversation、冻结原始请求摘要和首次接纳来源引用、保存用户消息、创建 Turn。数据库唯一约束决定唯一执行者。
- 相同 request_id 与相同规范请求返回原 Turn；内容冲突返回 409。执行开始前接纳失败必须关闭执行路径。
- 对话删除级联清除内容，仅保留不含请求正文的最小 request_id 摘要墓碑；旧请求返回 410，不能创建新对话。新请求标识独立执行。
- 先写 repository 测试：并发接纳、同键冲突、独立键、事务回滚、重启读取、删除及 ID 重用。

## 2. 接入运行时与传输

- `api.py`、`pilot_runtime`、`chat_transport.py` 接入接纳结果，避免已有用户消息被重复持久化。将任务标识绑定到本次执行，关联消息及操作来源。
- 规范请求摘要与来源版本快照分离；重试先查原任务，不重新加载来源版本。失败与中断仅记录已知事实。
- 返回 task/request 标识；重复调用只读原状态，不能隐式再启动执行或生成标题。
- 测试同步、SSE、确定性路径、Pending/Confirm、断连、接纳响应丢失、Journal 关闭和 Provider 调用计数。

## 3. 时间线存储与恢复

- 新增当前 Item 与提交变更索引，保存稳定 item_id、turn_id、类型、schema_version、来源引用、单调 revision、展示摘要、ordinal 与 change_seq。
- 单事务更新 Item 与 change；ordinal 表示首次出现顺序，change_seq 表示提交可见性。
- 实现快照与增量 API，游标绑定当前对话及认证边界。分页固定高水位；无效或不受支持游标明确要求重新同步。
- 展示修复只读取 Message、Ledger、ProductAction 等权威来源。无变化不增版本；删除写墓碑并清除旧内容副本。既有 P1 presentation API 保持源数据只读。
- 测试旧 Item 更新不丢失、乱序响应、快照分页、删除、重启、来源修复与无 Provider/业务写入。

## 4. 客户端恢复

- `web/src/services/chat.ts` 在逻辑提交时创建高熵 request_id，传输结果未知时保留以供恢复；新的提交使用新 ID。
- types/services 与共享 Pilot/Haru controller 接入任务身份和增量时间线；按 item_id 和 revision 合并，不用 hash 判断新旧。
- 恢复只调用读取 API；保留 P1 失败提示、重试入口与原审批/撤销命令。
- 前端测试覆盖重复提交身份、刷新/切换面板、乱序增量和删除墓碑；内置浏览器验证实际交互。

## 5. 验证与交付

- 更新 ADR 与接口契约，记录保留策略、失败语义和兼容范围。
- 运行新增测试及受影响 runtime/API/persistence、前端测试，ruff、mypy、前端构建。
- 启动独立子代理审查 schema、接纳/执行边界、隐私删除、游标与前端恢复；修复后验证受影响范围。
- 检查 diff 和工作树，仅暂存本任务文件；按仓库规范分开执行 add 与 commit。汇报实际结果与剩余风险。

## 6. 验证结果与限制

- 架构契约见 [ADR-0008](../../architecture/decisions/0008-persist-pilot-turns-and-timeline.md)。新增表由现有初始化创建；破坏性数据变化：无。
- 后端 runtime/persistence/transport/confirmation 与 action presentation 回归：274 项通过。新增接纳、API、时间线测试分批通过；最终隐私清除回归所在时间线测试 6 项通过，受影响 API 复测 9 项通过。
- 前端全量测试曾通过 25 文件、268 项；后续审查修复后，ChatPanel 交互与布局 71 项、提交服务和恢复组件 23 项通过。最终前端构建通过。
- 修改的 Python 文件通过 ruff；`mypy --platform win32 src` 通过（173 个源文件）。
- 内置浏览器使用隔离临时数据库和替代模型验收：已完成回执、待确认卡片、Pilot/Haru 切换、刷新恢复、响应丢失后原 ID 重试、直接读取原任务恢复审批状态均通过。恢复和重试没有增加模型或标题生成调用，用户消息未重复。
- 两个独立子代理分别检查接纳/前端恢复与来源/隐私边界；修复了上下文冻结、迟到恢复导航（包括查询期间发起新提交）、当前会话强制刷新、跨会话重试状态和失效快照清除事务的问题，并复测受影响范围。审查提出的业务对象软删除清除建议未采纳：普通软删除保留历史安全回执，权威 Message/Ledger 删除才触发内容清除，区别已明确写入 ADR。
- 本次是 P2 功能交付，未执行完整 release gate、Docker、安装或真实 Provider 验收。替代模型浏览器验收不能替代真实 Provider 验收。
- 保留上限、历史版本增长和进程中断只读恢复的限制见 ADR。损坏数据库中异常跨会话消息关系可能使投影返回错误；当前按失败关闭处理，不跨会话展示内容。
