# ADR-0007: 从业务事实投影共享动作展示

- Status: Accepted
- 日期：2026-09-08
- Decider：用户授权实施的 Harness 交接方案 `5b3bbb2` §6
- 依据：[P0 确定性回执](0006-edited-confirmation-receipts.md)、Harness P1 共享展示契约

## Context

Pilot、Haru 与产品动作页面分别解释确认和完成状态，容易把执行成功、撤销结果、
网络响应与诊断完整性混为一谈。现有消息、Pending、Ledger 和 Product Action
已经拥有业务身份与权限边界；展示统一不应再创建执行器、确认凭据或 Timeline。

## Decision

采用两个只读 Builder 生成 `ActionPresentationV1`。Agent 读取原消息、Pending 与
已校验 Ledger，Product Action 读取自身已校验提案、决定、提交与补偿绑定。
标题与摘要沿用现有 Metadata 展示能力；P0 回执复用原可信交付。

决定、执行、证据和撤销使用正交状态；例如已保存与撤销冲突可以同时成立。
无法证明历史批准方式时返回 unknown，不以当前对象恰好等于目标值证明原操作成功。
当前可用动作与历史事实分开计算；对象来源失效、权限与版本检查仍由原命令通道执行。

DTO 只携带公开操作身份、可读状态、摘要、来源与展示指纹、能力提示，不携带确认
token、proof、完整内部参数或数据库异常。来源和展示 revision 是不透明指纹，
不能按字符串顺序推断新旧，也不是持久同步游标。

`PilotTurnItemV1` 按既有消息顺序投影，使用 `message:<message_id>` 与
`agent_operation:<operation_id>`。同一操作待确认到终态更新同一逻辑 Item。
无法可靠关联的旧消息不凭正文、工具名或参数摘要猜测合并。未保存增量使用明确临时
身份，收到持久消息后以服务端快照替换；P1 不承诺持久 Turn 或增量同步能力。

Pilot 与 Haru 共用 Controller 的一次展示读取与原命令所有者；外壳不拥有新的
Provider、确认或撤销请求。产品动作保留自己的 owner draft 和确认/补偿通道。
展示响应只适用于发起读取时的会话与可见消息状态，失效读取不能覆盖当前会话。
网络结果未知可形成局部展示提示，但不能抹去服务端已验证的提交事实。
不支持的展示版本禁用相关按钮并显示最小状态。

同一会话刷新期间保留已有操作节点，只允许只读刷新，等待新快照后恢复可用命令；
新会话不得沿用旧会话快照。Readiness 历史输入证明读取操作创建的不可变版本，
撤销移动当前版本指针不能抹去原提交证明。

## Consequences

共享组件统一核心状态，保持密度与编辑表单由各入口决定。只读展示故障不会重复
执行业务；原消息和已有命令所有者仍承担兼容与恢复责任。
历史证据缺失时展示可能较少；P1 不追溯补写不存在的过程，也不依赖 Journal。

不新增持久表或重置数据。回滚可停止使用新增展示接口与组件，原执行协议继续可用；
仍须遵守 ADR-0006 的新策略读取与恢复限制，不能直接降级到不识别 P0 的执行器。
断线后继续执行与持久展示同步分别由后续 P3B、P2 实施。

## Alternatives Considered

1. 各入口在前端重新推断工具状态：重复维护能力与文案，无法验证 Ledger 与来源，
   未采用。
2. 同时引入统一执行器和持久 Timeline：扩大 P1 范围，混合权限、执行与展示职责，
   未采用。
