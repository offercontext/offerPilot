# Mock Interview 追问质量与幂等键修复设计

日期：2026-08-16

状态：已由用户批准实施

## 背景与根因

真实快速练习 Attempt 10 的第 2、3 轮分别完成了新的 Provider 调用，且输入均包含已回答轮次；问题不是前端重复渲染、旧 HTTP 响应重放或上下文缺失。根因有三项：

1. 提问提示只约束 JSON 与证据格式，没有要求后续轮次必须形成新追问。
2. 服务端只验证问题非空和证据合法，没有拒绝历史重复问题，也没有要求后续问题引用最近回答。
3. 前端在问题生成成功后保留了上一次 `questionKey`，导致后续轮次继续复用该 key；后端目前按 `turn_no` 隔离，所以它不是重复问题的直接原因，但违背每个新操作使用新 key 的边界。

## 目标行为

- 第 1 轮可以基于冻结 JD、简历或准备资料提出起始问题。
- 第 2 轮及以后必须生成不同于全部历史问题的新问题。
- 后续问题必须至少选择最近一轮回答的 evidence ID，形成可审计的追问关联。
- 提示要求问题聚焦最近回答中的具体实现、难点、取舍、结果或验证方式，不得只改写或复述历史问题。
- 问题规范化后与历史问题重复时返回终态语义失败，不进行格式修复，也不写入新题目。
- 每个新问题操作生成新的 `questionKey`；只有结果未知恢复才复用原 key。
- 现有冻结快照、证据 ID 展开、lease/CAS/fencing 和证据严格校验保持不变。

## 服务端契约

新增确定性问题规范化：Unicode `NFKC`、去首尾空白、折叠连续空白、统一英文大小写。仅用于重复比较，不改写持久化问题文本。

`generate_question()` 在后续轮次执行：

1. 构造历史问题规范化集合。
2. 要求 `evidence_ids` 至少包含最近一轮回答对应的 evidence ID。
3. 拒绝规范化后命中历史集合的问题，失败类别为 `duplicate_question`。
4. 拒绝未引用最近回答的问题，失败类别为 `missing_latest_turn_evidence`。

这两类是语义错误，不允许通过格式修复重试。

## 前端状态

问题生成成功后，Reducer 将 `questionKey` 清为 `null`。下一轮首次生成时创建新 key；若该请求进入 `result_unknown`，状态继续保存这次 key，原 key 重试语义不变。

## 测试与验收

- AI 纯函数：重复问题失败；缺少最近回答证据失败；合法追问通过；首题不强制 turn evidence。
- API：重复问题进入既有 `mock_interview_unverifiable` 终态，不写入可回答题目。
- 前端 Reducer/挂载：连续两轮成功请求使用不同 key；结果未知重试保持同 key。
- 回归：证据 ID 服务端展开、网络未知恢复、终态重新开始、生产构建和真实 Provider 单次验收。

## 非目标

- 不引入问题相似度模型或额外 Provider 调用。
- 不用关键词或向量相似度猜测语义重复；本期只拒绝确定性的规范化完全重复。
- 不改变公开 API、数据库结构、最大轮数或复盘契约。
