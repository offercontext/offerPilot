# 面向新手的 Agent 学习入口与首篇内容说明

更新：2026-10-08。状态：[学习入口](../learn/README.md)已串联二十二篇概念入门与[六篇 Harness 进阶导读](../learn/advanced/README.md)，留待统一审阅。本轮将 Agent Loop、职责拆分、写操作审批、上下文投影、取消与恢复、运行记录对应到固定版本的源码和设计记录，并补充流程图。相关的 14 个现有测试已通过，具体节点与验证边界统一记录在进阶入口；未运行真实模型、产品界面或服务重启实验。首篇仍使用明确标注局限的旧版截图；新素材按用户要求保留占位与采集说明。交互演示与读者试读尚未提供，首篇正式发布前仍需重录前后一致的素材。

## 面向谁，先学会什么

面向不懂 Agent 的人，包括不会编程、没有做过模型调用或 Agent Demo 的读者。入门不要求安装项目、配置模型、读源码或先理解 Harness。

内容方向：**跟着一个开源求职助手，一步步看懂 Agent 是怎么工作的。** 从一个能理解的功能开始，认识背后的概念，愿意继续时再打开代码。OfferPilot 继续服务求职者，仓库增加学习入口；材料上线后再对外承诺相应内容。

第一篇的成功标准是读者能用自己的话说清楚：这件事里，AI 做了什么，程序做了什么，为什么两者需要配合。实现完整系统所需的编程基础在后续逐步补充。

## 三层入口，按兴趣选择

| 层次 | 读者做什么 | 材料与前提 |
| --- | --- | --- |
| 看懂 | 看一个例子，说清任务是怎样完成的 | 截图或短演示、一张简单流程图、日常语言解释；不要求读代码 |
| 体验 | 在准备好的演示中，分别选择确认保存或取消本次修改，观察结果 | 虚构数据与明确操作提示；不要求搭建整套系统。演示未提供前不把自行安装作为替代门槛 |
| 实现 | 选择性地阅读相关代码，逐步尝试一个小改动 | 单独说明并补充函数、接口、数据库等前置知识；源码与实验明确标为可选进阶 |

完成第一层本身就有价值，不要求每位读者继续学编程或完成全部层次。

## 首篇：你说“帮我记一场面试”，AI 到底做了什么？

贯穿场景：读者已经有一条虚构投递，请助手记录一场面试。首篇新编请求为“2026 年 9 月 14 日下午三点，我要参加云岚数据的线上面试，预计一小时，帮我记一下”。这不是旧截图对应对话的原话。旧图中准备事项的来源尚未在本文提供，正文明确其用途仅为认识界面。后续若使用“明天”等相对时间，演示需标明当天日期并展开为具体日期。

先展示任务全貌，用下面这条教学流程帮助理解；它是概念示意，不是已经验证过的界面录像：

> 你提出请求 → AI 识别任务、请求查找投递 → 程序提供相关记录 → AI 提出保存建议 → 你核对并确认 → 程序保存 → 在记录中查看结果。

文章只展开三个重点：

1. AI 把日常语言变成下一步动作建议；投递信息来自程序提供的记录，不是 AI 凭空知道的。
2. 程序提供查询与保存功能，并实际执行获准的操作。AI 回复“记好了”，不能单独作为保存成功的证据，要能在记录中看到结果。
3. 人负责核对公司、岗位和时间，决定是否保存。选择取消本次修改，就不新增这场面试日程；确认也不代表建议一定正确。

篇幅控制为一个场景、一张简单流程图、一段分工解释；截图或短演示用于观察保存前后。先展示正常过程，不要求读者排查故障、搭建环境、运行测试或理解数据库原理。

看完后按需介绍名字：理解和提出动作的部分叫模型；供它调用的查询、保存功能叫工具；当前任务需要的信息属于上下文。把这些环节接起来、管理执行与停止等工作的程序，是 Harness 的一部分。读者不必背术语，也不把这张简图当作所有 Agent 的固定工作方式。

## 二十二篇的教学范围与收尾标准

完整标题和阅读导航统一维护在[学习入口](../learn/README.md)，这里记录分段目的与作者边界。

| 段落 | 章节 | 读者应形成的认识 |
| --- | --- | --- |
| 看懂任务 | 1—7 | 模型、工具、用户和 Harness 怎样配合；在第六篇正文正式认识 Harness |
| 拆开输入与过程 | 8—11 | 提示词、工具说明、上下文和运行记录各有什么作用 |
| 处理中断与边界 | 12—17 | 区分重试、取消、恢复和记忆；理解权限与运行限额 |
| 验证、扩展与总览 | 18—22 | 模型适配、任务组织、评估与可选扩展怎样放回整体；用综合场景检查理解 |

本轮收尾以核心职责覆盖为准：输入与上下文、模型调用与工具协议、循环与任务组织、授权与执行隔离、持久状态与恢复、重试与重复操作、取消与迟到结果、记忆边界、资源预算、观察与评估均有对应正文。框架、MCP、Skills 和多 Agent 说明其可选作用，不作为所有 Harness 的固定组成清单。

二十二篇完成的是不要求编程基础的概念路线。[进阶路线](../learn/advanced/README.md)另行说明 Python、JSON 和数据库读写前提，以具体失败场景解释事务、租约和恢复，再链接源码与现有测试。不声称已经交付所有协议细节或独立可运行课程；真实模型实验仍待后续，不为覆盖术语而给产品增加功能。

图示服务于各章的问题：入门篇展示任务中的分工与分支，进阶篇展示实现中的控制边界。正文提供静态 SVG，保留折叠的 Mermaid 图源以便维护。需要实际界面或诊断证据的位置保留用户要求的素材占位；图源、教学表和示意输出均不得冒充运行记录。

## 作者需要保留的区别

- 各篇虚构情境不自动构成连续运行数据。提示词对照不是实测，工具卡不是当前 schema，上下文例子不是现有配置，故障表不是实际事故。
- 查询成功但结果为空，与读取失败分开。同一公司多岗位的列表请求不必追问；修改某一条却无法定位时才补充信息。
- 保存建议、用户确认、实际执行和结果分别核对。结果未知时不盲目重试；重复请求需要对应同一操作，内容改变不能沿用旧确认。
- 停止不等于撤销。恢复前检查任务状态和当前记录；对记录的检查要与实际写入协调，不能用旧卡片覆盖新修改。
- 记忆不等于当前上下文，偏好不等于授权；资料里的文字不自动升级为指令。权限检查、工具限制与执行环境需要共同配合。
- 预算示例不是产品默认值或精确费用承诺。模型切换要保留执行状态，适配必要的服务约定，不能把未知操作重放一遍。
- 评估案例只是设计，尚未执行；模拟模型检查不证明真实模型表现。Agent runtime harness 与 evaluation harness 的用途分开解释。
- 第六篇起 Harness 进入正文主线。各篇仍从日常问题出发，不将运行职责等同于独立服务、整个产品，或“有了就必然正确”的保证。

## 首批交付与读者反馈

首批从一个学习入口和一篇完整的“看懂”内容开始，现有二十二篇概念入门与六篇源码进阶，等待统一审阅。准备好的交互体验可以随后补充，不把一组工程实验作为首篇上线的前置条件。文章清楚标注哪些材料已提供，哪些层次尚未开放。

先找少量没有 Agent 背景的读者试读，尽量不由作者在旁补课。请他们回答：“谁提出要保存什么？”“谁真正保存？”“只看 AI 说记好了，能确定保存了吗？”记录陌生词、卡住的位置和需要作者解释的地方，再调整材料；不把测试通过、术语记忆或独立编码作为入门验收。

首轮先判断能否看懂、是否愿意了解下一步。学习反馈、产品使用和团队维护成本分别记录；不要求读者贡献代码，也不把阅读量或 Star 当作学会的证据。

## 制作约束与可选进阶

以下供内容作者使用，不放在新手第一屏：

- 使用虚构投递和隔离数据，不发送外部消息。模拟流程标为教学示意；声称真实界面或保存成功时，须实际走查并注明对应版本。首篇不要求读者提供模型凭据或承担调用费用。
- “面试日程”对应 `ApplicationEvent`、`application_events` 和 `event_type=interview`，不混用面试笔记或模拟面试记录。产品约束沿用 [AGENTS.md](../../AGENTS.md) §6，不为教学关闭默认人工确认。
- 需要真实投递匹配、确认卡和保存结果的素材时，在素材对应版本核对行为；本文不将教学顺序当作当前代码的精确调用顺序。
- 正式发布前重录：使用明确公司、岗位、开始时间、线上地点、一小时时长的同一条请求；准备事项未提供时不自行补写。确认卡与保存后的日历逐项对照，未提供的信息展示如何补充或确认。保存日期时间应无需人工事后修正；如仍需修正，应记录问题并保留图旁说明。正文先展示保留目标信息和按钮的局部图，完整界面置于展开区；记录实际版本与验证方式。
- 第十二至十四篇用日常场景解释操作识别、重复请求和恢复；事务及并发实现由进阶第三、五篇展开。讲响应丢失时，区分“调用方暂不知结果、服务端可查询已提交结果”与“外部执行结果无法确定”。这些不是首篇学习要求。
- 源码导读固定到 `c0a447bbe7be8976fe9a53c2bcbf3b91dad0eeac`，源码入口和验证记录维护在进阶各章及其入口。后续更新源码基线或补做实验时，重新核对受影响机制和命令；不将本轮局部测试通过扩大成产品完整验收。
