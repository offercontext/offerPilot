# ADR-0013: 持久化受当前模型能力约束的原生图片消息

- Status: Accepted
- 日期：2026-10-13
- Decider：用户确认图片消息实施方案（“同意，开始实施吧”）
- 依据：现有 Pilot Runtime、共享会话控制器、Provider 配置与上下文预算契约

## Context

Pilot 需要接收截图等图片资料，支持纯图片提问、图文混合、多轮追问与写入确认后的恢复。
业务 `attachments` 是投递、Offer、简历的引用，不能承载上传文件；Base64 也不能进入浏览器
恢复记录、数据库消息或 Journal。图片上传不扩大业务写入授权。

## Decision

复用 `supports_vision`，将它贯通设置 API/UI、冻结 Provider 与执行链指纹。图片入口取决于
当前主模型启用、已配置密钥、声明图片能力且适配器在支持列表中。备用模型不替代这个入口判断。
修改模型、接口或供应商后需重新确认图片能力，连接测试与收费的图片样例测试独立。
不新增 `multimodal_provider_id` 隐式路由、OCR 降级、独立视觉 Agent 或自动知识入库。

请求新增有序 `image_attachment_ids`；`message` 可以为空，但文本与图片不能同时为空。
响应与时间线使用 `image_attachments`，`content` 继续是字符串。
完整 Pilot、业务侧栏与 Haru 共用内存中的图片草稿。Haru 采用输入框上方的缩略图托盘，支持选图、
粘贴、拖入、失败重试和纯图片发送；历史图片可放大和再次引用。展开到 Pilot 或收起窗口不丢失草稿。
只有输入框显式发送才携带当前范围的图片，快捷操作不携带隐藏图片草稿；待确认或执行期间禁用发送。
选择、粘贴、拖拽使用同一上传链，保留混合粘贴的文字。受理前保留草稿，受理后只清除本次图片；
相同未确认提交重用请求身份。浏览器持久恢复记录仍只含请求与 Turn 身份。

新增 `chat_attachments`、`chat_message_attachments` 及 `chat_messages.image_refs_json`。
上传文件真实解码后拒绝动画及超限尺寸，校正 EXIF 方向，移除元数据，规范化为 PNG/JPEG。
每条最多 4 张，每张输入及规范化结果最多 10 MiB，单条最多 20 MiB，最多 2000 万像素和
10000 px 单边。原始文件不长期保存。不可变引用包括 ID、SHA-256、真实 MIME、大小、宽高和
`image-normalize-v1`；哈希对应实际发送给模型的字节。SQL 触发器禁止覆盖资源身份。

文件先写入并 fsync，之后才登记资源。受理在同一 SQLite 写事务中校验范围与文件、计算包含
图片顺序/哈希/规范化版本的请求指纹、建立用户消息与关联并登记 Turn。不存在“已受理但尚未
绑定消息”的窗口，因此不再增加独立的临时 Turn 图片 pin 表。GC 使用同一写锁与关联判定，
保留有消息引用的资源（包括运行中、待确认及恢复中的消息）。未绑定资源超过 24 小时清理；
启动及每小时收集，硬删对话后立即收集已脱离资源。进程重启遵循原 Runtime 状态机，不重放模型调用。

图片接口沿用共享 Token 与会话/实体范围，禁止跨会话重用已绑定资源；预览通过鉴权请求获取 Blob。
未绑定图片按上传时的 context 校验；绑定后归属该会话，用户显式变更会话 context 时，历史图片和该会话的上传草稿继续随会话使用，不能借此转移到其他会话。
图片文件不公开挂载，URL 不携带 Token。删除会话或实体不可见后拒绝预览与模型读取。
备份包括数据库与 `chat-images` 文件。读取时核对不可变元数据与内容哈希，损坏资源明确失败。

`Message`、`FrozenMessage`、历史与准备快照携带引用，Base64 只在 LiteLLM 适配边界生成。
供应商 `provider_blocks` 继续保存推理等字段，不接受旧的未管理 `provider_blocks.images`。
当前图片必选，历史图片随完整对话组选择。先用主模型预算投影，再按选中的图片需求过滤备用链，
并按保留候选重新投影。图片不能为 fallback 静默转成文本。

预算策略 `model-surface-budget-v3-images` 保留现有文本及工具字节上限；图片另按
`image-patch-upper-bound-v1` 计费：每张 `1024 + 4 × ceil(width/32) × ceil(height/32)` 估算单位。
这是产品的保守预算策略，不是供应商计费承诺；具体接口仍需样例验证。单次上下文最多 8 张、
图片总量最多 20 MiB，序列化图片请求体最多 32 MiB。超限历史按整轮省略，并在模型上下文与
审计信号中明确“本轮未读取原图”；必需图片不合预算则失败。摘要不覆盖图片消息。
模型错误转为不含图片载荷的诊断，图片样例测试设置 30 秒网络超时、128 输出 token，不自动重试。

## Consequences

图片可以跨历史、确认与重启保持同一内容身份，同时保留 HITL 与请求幂等。
代价是本地存储与图片传输开销；每次调用重新解析需要的本地文件。保守估算可能要求用户裁剪长截图。
图片能力声明不证明兼容接口实际可用，样例测试是可选验证，真实识别准确率仍由模型决定。
迁移为增量建表/加列，旧文本消息默认空图片列表，无开发数据 reset。

## Alternatives Considered

1. 在消息与浏览器恢复记录中持久化 Base64：放大存储、请求与日志风险，且难以统一文件清理，因此不采用。
2. 自动路由视觉模型或 OCR 后交给文本模型：改变用户选定的主模型和费用路径，丢失原图语义，因此不采用。
3. 图片只用于首轮、不保存：多轮追问与确认后恢复会丢图，因此不采用。
