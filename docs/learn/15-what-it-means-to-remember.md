# 上次说过的事，助手为什么不一定记得？

你上次告诉助手：“我更希望在下午面试。”过几天新开一段对话，它却没有考虑这个偏好。

这未必是模型突然变笨了。先要弄清楚，你所说的“记得”，指的是哪一种信息被留下、又有没有在这次交给模型。

**以下偏好与保存方式均为虚构教学示意，不代表 OfferPilot 已提供相应记忆界面或自动记忆能力。**

## 软件里可以有几种不同的“留下来”

| 留下的内容 | 用来做什么 |
| --- | --- |
| 这次对话中刚说过的话 | 帮助理解当前交流 |
| 一份正在等确认的修改建议 | 接着处理尚未结束的任务 |
| 已保存的面试日程 | 记录具体哪场面试、什么时间 |
| 经用户明确要求保存的长期偏好 | 在以后相关任务中作为参考 |

这几种信息的用途不同。“希望下午面试”不是一条已经安排好的下午面试；一场待确认的改期，也不是永久偏好。

技术资料常把当前会话的信息与跨会话保留的信息分开讨论，可参考 [LangChain 的记忆概览](https://docs.langchain.com/oss/python/concepts/memory)。这里先用生活里的区别来理解，不必记分类名字。

## 保存过，也要在合适的时候取出来

假设一个教学助手支持保存偏好，并按产品规则记录了你的明确要求：

> 偏好：如果时间可以选择，优先考虑下午。
>
> 来源：用户主动说明，希望以后安排时参考。

下次你让它比较两个可选面试时段，程序可以取出这条偏好，和候选时间一起交给模型。模型才有机会根据这些信息提出更符合你习惯的建议。

**把偏好存进软件，和把它放进本次上下文，是两个环节。** 如果没有保存、没有取到，或本次没有提供，模型仅凭这次看到的资料就不能可靠地使用它。

这里通过保存和再次提供信息来实现“记得”，并不要求重新训练模型。

## 偏好要允许变化，也不能替你授权

你后来说明：“这个星期上午更方便。”助手不能固执地沿用旧的下午偏好。程序需要保留信息的来源和适用范围，遇到矛盾时结合当前明确要求处理。

同样，一次特殊安排不一定该被永久总结成个人习惯。你今天选了上午，并不自动表示以后都喜欢上午。

一个支持长期偏好的产品，还应让用户有办法检查、更正或删除这些信息，避免错误印象一直影响后续回答。

即使记住了“优先下午”，也只是帮助提出建议，不能据此直接替你把所有面试改到下午。偏好不等于对一项具体修改的确认。

## Harness 在这里连接什么

记忆可以由独立的保存功能管理。Harness 按当前用户、当前任务组织信息，把相关偏好提供给模型，并避免把另一位用户或无关会话的资料混进来。

已保存的业务记录仍要从相应记录中核对。例如记忆里一句“面试大概在周二”，不能覆盖后来正式改到周三的日程。

对读者而言，关键问题不是“AI 有没有无限记忆”，而是：**留下了什么、为什么留下、什么时候取出来、现在还适不适用。**

## 用自己的话说说看

助手记得你“通常喜欢下午面试”，你今天明确要求把一场面试记在上午十点。它能因为旧偏好而自行改成下午吗？
