# 逐字引用定位：离线原型

目的：测试让程序计算引用位置，是否能减少模型数错字符的问题。
本目录没有接入产品、旧 validator、付费 runner 或工作流；不调用模型或网络。
它不修改已经失败的响应，也不产生“原实验通过”的结论。

## 输入与规则

输入是可信调用方提供的 `sources=[{id,text},…]`，以及模型候选的
`source_id`、非空逐字 `quote`。来源正文仍是数据，不是可执行指令。

- 仅在指定来源内做精确字符串匹配；来源 ID 必须存在且唯一。
- 零匹配或多匹配一律拒绝，包括 `aaa` 中 `aa` 的重叠匹配。
- 不做模糊查找、Unicode 正规化、修饰引用、选第一处或自动换来源。
- 返回 Python Unicode code point 索引，起点包含、终点不包含。
- 组合字符及 emoji 不能被截断：起止须落在来源的完整扩展字素簇边界。
  使用现有锁文件已包含的 `regex` 的 `\X`；索引仍不是字素簇序号。
- 本原型最多 8 个来源，每个来源最多 4096 code points；引用最多128。
  超长、空白、非字符串、非法来源 ID、重复来源、孤立 surrogate 均拒绝。
  这些是可审阅的原型资源界限，不是已验证适合所有业务的生产协议。

## “过宽”引用的边界

大于128 code points 明确拒绝。唯一且不超过128的整段来源可被定位，
但程序不判断它是否过于宽泛、是否与结论相关、是否省略关键上下文。
不能把128以内自动视为充分或最小证据；这些仍需要独立语义评审。
一个短而唯一的词也不一定支持模型结论。

## 对本次失败的意义

原始 s01 响应保留在
`../../scripts/companion_ai_validation/tests/fixtures/shadow-s01-40812959831-response.json`，
SHA256 `91678126eb9d71037bccfdbbad462ad5062e6401ba97768a04511a61d6f2075b`。
原值 `start=0,end=0` 配51字符的非空引用，仍必须由旧 validator 拒绝。
离线把相同逐字引用作为**新协议候选输入**，程序可定位到 `[0,51)`；
这是原型测试，不是回填或修复旧响应，不改变本批失败、49次累计账本。
`ambiguous` 本来就是该例预登记备选标签；定位成功不裁决它是否正确。

## target 还有没有同类风险？

现六例的 target 范围由实验预先固定，提示词要求原样返回，并由旧 validator
比较整个 target 是否完全一致。模型不需要重新计算，但仍可能抄错数字或文本。
因此新引用协议只消除了 evidence 数字符风险，并没有保证 target 永不失败。
未来可考虑由调用方持有固定 target、模型只引用 target ID；这属于另一个
协议选择，本原型不擅自实施，也不改变原先输出 schema。

## 取舍与下一步

值得作为下一轮协议候选：定位失败能明确分为不存在、多处或字素边界问题，
无需让模型算 offset，也没有偷偷修饰文字。但重复引用会拒绝一些本可解释的
回答；原型不自动让模型补答、不追加调用。若要消歧，可另行设计预编号来源片段，
不能直接放开“选第一处”。

上线前仍需决定引用长度策略、重复文本处理及 target 回传方式，检查实际模型
是否遵守新输出格式，并做独立语义评分。目前只有离线确定性证据，没有新模型
成功率或产品效果证据。任何真实新批次都必须另行决定并承接49次历史；不自动
补跑本批未尝试的五例，不重用旧 R，不改变权限、变量或 PR #51。
