# 动手台阶：一次待确认新增，为什么不会写两遍

这个可选小实验接在[四篇短路线](../README.md)之后、[源码进阶](../advanced/README.md)之前。不需要模型密钥、数据库、网络服务或安装 OfferPilot 依赖；只需要 Python 3.10 及以上，以及简单的函数和列表知识。

它沿用同一场面试：云岚数据 · 测试开发，2026 年 10 月 15 日北京时间 15:00，线上，60 分钟。数据仅存在于本次进程内存，不会读取或改变你的 OfferPilot 数据。

## 先预测，再运行

一个固定返回的模拟模型先请求读取投递，再提出新增日程。你先猜三个数量：

1. 建议已经形成、尚未确认时，有几条日程？
2. 明确确认之后，有几条？
3. 将同一个操作的确认重复一次，又有几条？

在**包含本实验文件的教程 checkout 根目录**运行下面的命令，路径从这里开始计算。它应能看到 `docs/learn/examples/mini_harness.py`；不要切到旧产品源码快照寻找新实验。

```sh
python --version
python docs/learn/examples/mini_harness.py --confirm
```

若系统把 Python 3 命令命名为 `python3`，相应替换即可。`--confirm` 明确选择在实验中模拟用户确认；脚本随后重复的是同一份确认，不会重新请模型生成建议。

关键输出应为：

```text
待确认：0 条日程；操作 operation-1
确认后：1 条日程；日程 #1
再次确认同一操作：1 条日程；返回原日程 #1
```

脚本也用断言检查这些数量，以及两次确认返回相同记录编号。每次启动都是一个全新的内存实验；这不是跨进程持久化演示。

## 换一个决定

不带参数时，只形成建议并停在待确认；`--reject` 则模拟拒绝：

```sh
python docs/learn/examples/mini_harness.py
python docs/learn/examples/mini_harness.py --reject
```

两次运行都应保持 0 条日程。再次启动带 `--confirm` 的脚本会建立另一个全新实验，不是让上一次已拒绝的操作复活。程序内部也拒绝确认已拒绝的操作。

## 顺着三个地方读代码

打开 [mini_harness.py](mini_harness.py)，先找下面三个方法：

| 方法 | 观察什么 |
| --- | --- |
| `prepare()` | 把读取结果按调用 ID 交回来；形成新增建议后返回操作 ID，尚未保存日程 |
| `confirm()` | 只保存原操作绑定的不可变建议；已有 `committed` 结果时直接复用 |
| `reject()` | 将待确认操作记为拒绝；拒绝不能撤销已经提交的日程 |

`ScriptedModel` 的两步回复是预先写好的，它不会理解用户意图，也不会根据资料推理。这让实验聚焦在程序控制流；它不能证明真实模型会选择正确工具。

消息里的 `read-1`、`write-1` 用来关联调用与结果；`operation-1` 用来识别这项待确认写入。实验只允许一个实例接纳一项任务，因此这些固定编号只在该实例内使用，不能直接用于多任务产品。

## 自动核对，而不是只看打印

从同一个仓库根目录运行：

```sh
python -m unittest discover -s docs/learn/examples -p "test_*.py" -v
```

[测试文件](test_mini_harness.py)检查读取消息配对、确认前不写入、保存字段、重复确认、拒绝与未知操作，以及默认命令的行为。测试真实调用这份实验代码，不需要 pytest 或真实模型。

可以做一个有针对性的练习：临时移除 `confirm()` 中复用 `committed` 结果的分支，再运行测试。重复确认会多新增一条，相应断言应失败。随后恢复该分支，确认测试重新通过。这样能看出测试保护了什么，而不只是记住输出的三个数字。

## 它刻意没有实现什么

这里只演示单线程、单进程的一项固定任务。没有持久化、并发事务、进程崩溃恢复、真实用户权限、完整参数校验、模型 fallback、租约或执行围栏；也没有编辑建议、补偿撤销和跨请求恢复。内存中“先查状态、再新增”的顺序，不能直接作为生产并发防重实现。

想知道生产中为何还要更多机制，可按问题读：[消息与循环](../advanced/01-agent-loop.md)、[事务内的审批与重复确认](../advanced/03-write-approval.md)、[停止和恢复](../advanced/05-cancellation-and-recovery.md)。产品源码的固定版本、依赖安装和测试命令见[进阶入口](../advanced/README.md)。
