# 语音面试陪练设计

状态：已复审通过
日期：2026-08-13
依赖基线：`f9adf8a`（录音回放、浏览器 TTS、本机识别与离线 Whisper 已具备）

## 1. 背景与目标

OfferPilot 已支持文字模拟面试、页面内录音、浏览器本地朗读、可选离线 Whisper 批量转写，以及用户校对后显式确认文字。当前缺口不是再增加一个语音入口，而是把这些能力组织成自然、可恢复、可解释的面试练习流程。

三期新增“语音面试陪练”：本地检测用户何时开始说话和何时停顿，顺序生成临时字幕，回答结束后执行最终转写，并基于本地音频测量与用户确认文本展示表达节奏复盘。

本功能不评价情绪、自信度、沟通能力、面试表现总分或录用概率，也不改变现有 Mock Interview 的回答确认与提交语义。

## 2. 方案选择

### 2.1 采用：半实时语音流程与确定性节奏复盘

- 浏览器本地 VAD 控制状态提示和录音分段；
- 离线 Whisper 顺序处理片段，提供临时字幕；
- 回答结束后生成最终转写，必须由用户确认；
- 使用可测量事实生成时长、停顿、语速和口头语统计；
- 设备能力不足时退回二期的录完后批量转写。

该方案在自然交互、隐私、成本和实现范围之间最均衡。

### 2.2 不采用：只增加实时字幕

实现较小，但无法解决朗读、聆听、停顿提示、确认和复盘之间割裂的问题，产品价值不足以单独作为三期。

### 2.3 不采用：云端实时语音 Agent

全双工体验更自然，但会引入持续音频上传、Provider 费用、网络抖动、打断处理和新的隐私授权。当前不引入云端 STT、语音克隆或实时 Provider 通话。

## 3. 用户流程

```text
朗读题目
→ 等待用户开口
→ 本地 VAD 检测有效语音
→ 分段录音并顺序生成临时字幕
→ 短停顿继续等待 / 长停顿只提示
→ 用户点击“完成回答”或达到 5 分钟上限
→ 完整音频执行最终离线转写
→ 用户校对并显式确认
→ 提交现有 Mock Interview 回答
→ 展示本题表达节奏复盘
→ 用户主动进入下一题
```

固定行为：

- 长停顿不会自动确认或提交回答；
- 达到 5 分钟只停止录音并进入校对，不自动确认；
- 临时字幕不进入正式回答；
- 只有用户确认后的最终文字沿用现有回答提交路径；
- 用户切题、重录、关闭 Drawer 或卸载页面时废止旧 generation 并清理资源；
- 进入下一题必须由用户主动触发。

## 4. 前端架构

### 4.1 `VoiceSessionController`

新增纯前端会话控制器，隔离录音、VAD、分段队列、最终转写与统计。公开状态为完整判别联合类型：

```ts
type VoiceSessionState =
  | { status: 'idle' }
  | { status: 'reading_question' }
  | { status: 'waiting_for_speech'; elapsedMs: number }
  | { status: 'recording'; elapsedMs: number; voicedMs: number }
  | { status: 'speech_paused'; elapsedMs: number; pauseMs: number }
  | { status: 'finalizing' }
  | { status: 'transcribing'; mode: 'segment' | 'final'; progress?: number }
  | { status: 'reviewing'; transcript: string; temporarySegments: TranscriptSegment[] }
  | { status: 'confirmed'; transcript: string; summary: VoiceDeliverySummary }
  | { status: 'error'; recoverable: boolean; message: string };
```

控制器不访问 Mock Interview API，不导航，不持久化音频，也不自行确认文字。组件只通过既有 `onConfirmTranscript` 把用户确认文本交给现有流程。

每次开始录音、重录、切题或关闭均递增 generation。任何旧 generation 的 VAD、解码、Worker 或转写结果必须丢弃。

### 4.2 VAD

VAD 只判断“当前是否存在可检测语音”，不判断语义或质量：

- 首选 `AudioWorklet` 计算本地 RMS、peak 和时间帧；
- 不支持 AudioWorklet 时，退回 `AnalyserNode` 定时采样；
- 开始录音后的前 800ms 用于噪声底线校准；
- 有效语音阈值为 `max(0.015, noiseRms × 3)`；
- 连续 160ms 超过阈值后进入 `recording`；
- 小于 1.2 秒的静音作为短停顿；
- 连续 2.5 秒静音进入 `speech_paused` 并提示，但不结束回答；
- 阈值、窗口和时钟必须可注入，测试不得依赖真实 sleep；
- 环境噪声持续过高、采样能力不可用或校准失败时，关闭自动提示并退回手动录音，不阻塞回答。

这些常量是交互阈值，不是候选人能力标准，不进入最终评分。

### 4.3 分段转写

- MediaRecorder 继续生成当前页面内的完整录音 Blob，供回放和最终转写；
- 同时把音频按约 20 秒切片，保留前一片最后 2 秒作为本地重叠上下文；
- 片段带稳定 `sequence`、generation 和本地时间范围；
- 同一时刻最多运行一个 Whisper 推理；
- 临时字幕严格按 sequence 合并，迟到片段不得越过新 generation；
- 重叠区域只用于上下文，合并时使用确定性前后缀去重，不让同一文本重复出现；
- 临时字幕只显示在当前页面，不写入回答、数据库或日志。

如果首个片段推理耗时超过片段时长，或等待队列超过一个片段，控制器停止继续安排半实时推理，保留录音并在结束后使用二期批量转写。该切换只影响体验，不改变确认语义。

### 4.4 最终转写与降级顺序

用户结束回答后，完整录音重新解码并运行最终转写；最终文本不直接采用临时字幕拼接结果。

固定降级顺序：

1. WebGPU 分段转写；
2. WebGPU 录完批量转写；
3. WASM 录完批量转写；
4. 浏览器原生本地识别；
5. 录音回放与手工整理；
6. 纯文字回答。

沿用二期规则：模型未由用户主动下载时不触发 Hugging Face 请求；WebGPU 同一 generation 最多自动降级一次 WASM；静音和异常重复文本不得生成正式转写；录音最长 300 秒。

最终转写失败时保留当前页面内的录音、临时字幕与手工输入入口。用户可以重试，但系统不会自动提交，也不会把临时字幕伪装成最终结果。

## 5. 表达节奏摘要

### 5.1 数据结构

```ts
type VoiceDeliverySummary = {
  totalDurationMs: number;
  voicedDurationMs: number;
  pauseCount: number;
  longestPauseMs: number;
  speechRateCpm?: number;
  fillerOccurrences: Array<{
    text: string;
    count: number;
    transcriptOffsets: number[];
  }>;
  source: 'local_audio_and_confirmed_transcript';
};
```

### 5.2 计算规则

- `totalDurationMs`：录音开始到结束的单调时钟差；
- `voicedDurationMs`：VAD 判定为有效语音的时间帧总和；
- 停顿：首次有效语音之后、最后一次有效语音之前，连续静音不少于 800ms 的区间；
- `pauseCount`：符合上述规则的区间数；
- `longestPauseMs`：上述区间的最大值；
- `speechRateCpm`：确认文本去除 Unicode 空白和标点后的 code point 数，除以总回答分钟数；总时长不足 5 秒或有效字符为空时不生成；
- 口头语：使用固定中文默认词表，按最长词优先扫描确认文本并返回 Unicode code point offset；同一字符区间不得重复计数；
- 词表通过纯函数参数注入，便于测试和以后扩展，三期不增加设置页或长期偏好存储。

摘要只陈述测量结果，不使用“优秀、较差、紧张、自信、流畅度分数”等评价语言。

### 5.3 生命周期

三期不新增摘要表、API 或数据库字段。`VoiceDeliverySummary` 仅存在当前已挂载的练习会话：

- 原始音频、PCM、VAD 帧和临时字幕不持久化；
- 确认文本继续按现有 Mock Interview 流程保存；
- 回答提交或页面关闭后释放音频资源；
- 摘要只供本次复盘展示，不从历史文本反推不存在的音频指标。

“未来可确认摘要快照”仅作为后续扩展边界：若真实使用证明长期趋势有价值，再单独设计由用户确认后保存的结构化统计记录。它不是音频文件，三期不建表、不预留字段、不提供入口。

## 6. 界面设计

### 6.1 回答中

- Haru 文本状态覆盖：朗读题目、等待开口、正在聆听、检测到停顿、本地转写、等待校对；
- 展示本地实时波形、当前时长和临时字幕；
- 长停顿提示固定为“可以继续，也可以完成回答”；
- 所有状态必须有文本，动画和波形仅作辅助；
- `prefers-reduced-motion` 下停止装饰动画，状态与操作保持完整；
- 用户始终可以暂停、继续、完成回答或切回文字模式。

### 6.2 校对与确认

- 完整转写显示在可编辑文本框；
- 临时字幕与最终转写必须有清楚标签，不能混为同一事实；
- 显示录音回放；
- 用户点击“确认使用这段文字”后才进入既有回答字段；
- 重录不覆盖已提交回答，开始前明确提示当前草稿会被替换。

### 6.3 表达节奏复盘

- 在已确认的本题回答下方展示独立“表达节奏复盘”卡片；
- 展示总时长、有效发声、停顿、最长停顿、语速和口头语；
- 每项带计算口径说明，不显示综合分和排名；
- 点击口头语定位确认文本位置；
- 点击停顿跳到当前页面内录音的对应时间点；
- 原始录音已释放或页面重载后，与音频相关的跳转不可用，不伪造历史入口；
- “重新回答”创建新一轮本地草稿，不自动覆盖已提交内容。

## 7. 隐私、网络与资源边界

- 模型下载是唯一允许的新增外联，且只能由用户明确点击触发；
- 从麦克风授权到回答确认完成，音频、PCM、VAD、临时字幕和最终转写阶段不得向 Hugging Face、AI Provider 或 OfferPilot 后端上传音频；
- TTS 仅使用浏览器 `speechSynthesis`，不调用云端语音合成；
- 页面日志、诊断信息和测试输出不得包含音频、PCM 或完整转写原文；
- 录音、切片、PCM 和 Blob URL 在重录、切题、关闭、提交成功和卸载时统一清理；
- 取消转写必须终止活动 Worker，不能只忽略返回结果；
- 模型缓存继续由设置页显式管理，与本次会话音频生命周期分离。

## 8. 错误与恢复

- 麦克风拒绝：保留文字回答并提供重新授权说明；
- VAD 不可用：退回手动录音，不阻塞 Whisper；
- 分段解码失败：停止临时字幕，继续保留完整录音；
- 模型忙或设备过慢：切换批量模式，不并发启动第二个推理；
- 最终转写失败：保留回放、临时字幕和手工编辑，不自动确认；
- 页面隐藏或设备休眠：暂停状态更新；恢复后要求用户继续或完成，不推断遗漏音频；
- 来源 generation 变化：所有晚到结果丢弃；
- 资源清理结果未知：禁止继续复用旧 Worker 或旧 Blob URL，重新初始化本地会话。

## 9. 测试策略

### 9.1 纯函数与控制器

- VAD 的语音、短停顿、长停顿、噪声、静音、阈值边界和可注入时钟；
- 状态联合类型的所有合法转换与非法转换拒绝；
- 20 秒分段、2 秒重叠、稳定 sequence、确定性文本去重；
- 单 Worker 串行队列、队列积压切换批量模式；
- generation fencing、取消、切题、关闭与迟到响应；
- 300/301 秒边界；
- 语速、停顿、口头语、Unicode、emoji、组合字符、空文本和极短回答；
- 摘要永不生成综合分或情绪判断。

测试使用 `ManualClock`、可控音频帧和 deferred Worker，不依赖真实 sleep、麦克风或模型下载。

### 9.2 组件与真实挂载

- 朗读、等待、聆听、停顿、转写、校对和确认完整流程；
- 长停顿不提交，5 分钟只结束录音；
- 临时字幕不进入回答；
- 最终确认只调用一次既有回调；
- 关闭和重录释放 MediaStream、AudioContext、Worker、PCM、Blob URL；
- reduced-motion、键盘、焦点、ARIA live、窄屏和深色模式；
- 模型下载以外，音频流程的 fetch、XHR、业务 service、导航和历史写入均为 0；
- 摘要不调用 AI，不写 Knowledge、Memory、Story 或 Application 状态。

### 9.3 浏览器验收

使用内置 Codex browser、亮色中文宽屏和候选人“筱哲”，展示：

1. Haru 朗读题目；
2. 等待开口；
3. 正在回答与波形；
4. 长停顿提示；
5. 临时字幕；
6. 最终转写校对；
7. 显式确认；
8. 表达节奏复盘；
9. 半实时性能不足时切换批量模式；
10. 关闭页面后的音频和 Worker 清理。

没有真实麦克风输入时允许使用 Mock 音频展示界面，但截图与报告必须明确标记；Mock 不能作为语音准确率、延迟或设备兼容性证据。

## 10. 范围与兼容性

本期允许修改前端 Mock Interview 语音模块、必要的 Haru 状态、设置说明、测试、第三方说明和验收报告。

本期禁止：

- 新增后端 API、数据库迁移或共享后端类型；
- 保存原始音频、PCM、VAD 帧或临时字幕；
- 云端 STT/TTS、语音克隆、声纹或说话人识别；
- 自动确认、自动提交或自动进入下一题；
- 情绪、自信度、能力评分、排名或录用概率；
- 将摘要写入 Knowledge、Memory、Interview Story 或其他领域。

破坏性变化：无。现有文字回答、一期录音回放、二期批量 Whisper、浏览器原生识别、Mock Interview API 和人工确认语义全部保留。
