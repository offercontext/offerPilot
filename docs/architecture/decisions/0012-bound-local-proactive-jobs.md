# ADR-0012：持久化有界的本地主动任务

- Status: Accepted（实现验证见关联计划）
- 日期：2026-09-09
- Decider：用户授权连续实施的 Harness 路线图 `5b3bbb2` §11（P5）
- 依据：[Runtime 所有权](0010-own-pilot-execution-in-runtime.md)、[Knowledge 架构](../knowledge-system.md)

## Context

Haru 可以提醒用户处理临近事项，但普通提醒不能默认授权模型费用，更不能自动投递、外部发送或
修改关键业务状态。重启、取消、源更新与迟到结果需要和执行所有权一起处理。

## Decision

主动功能默认关闭，用户明确选择投递范围。确定性提醒和模型准备草稿分别启用，并分别限制滚动
24 小时次数。支持投递截止、面试准备、七天未更新投递、已完成面试的复盘提醒和面试准备草稿。
本地服务未运行时不执行；启动只检查近期有效事项，不补发多日积压。

任务使用 SQLite 持久化，状态为 pending、leased、running、succeeded、failed、cancelled 或
result_unknown。原子认领记录 owner、lease、attempt、turn_id 和 execution_generation。待处理队列
最多 100 项，每次调度最多派发 4 项，任务记录最多保留 2000 项；可清理七天前的已知终态记录。

普通提醒确定性生成，不调用模型。准备草稿使用 P3 共享的有界 Runtime 工作池，单次调用、不使用
工具、不生成标题、不自动 fallback，最多 60 秒、1024 输出 token。日预算在派发前预留，不因重连、
未知结果或重启退还后重用。草稿只读取任务绑定的岗位和面试元数据，未知事实显式留待确认。

草稿不伪造用户聊天消息，不进入正式 Knowledge、面试笔记或业务成果。队列拥有单一输出槽，发布
事务同时校验 owner、turn/generation、lease、来源摘要值、启用范围、期限与安静时段，再提交终态。
真正需要业务写入时仍使用现有 Pending/Product Action，本模块不新增确认或 Undo 协议。

创建、实际 Worker 开始及发布前都核验来源。事件取消、时间变更、准备成果已生成、复盘笔记已存在、
投递删除或用户关闭范围会使旧任务失效。未使用 Readiness、Memory 或 Knowledge 内容的草稿不宣称
消费了这些来源。若以后加入这些内容，必须将其精确版本及撤回条件纳入同一发布围栏。

幂等键包含事项、类型、必要来源版本和触发时间；另按同一事项限制频率，防止修改版本绕过限制。
尚未开始模型的过期 lease 最多重认领三次；已派发模型的未知结果进入待核对，不自动重跑。
关闭功能取消未完成任务并请求 Runtime 停止，发布围栏不依赖 Provider 是否已物理退出。

到期时间保存为 UTC 秒，安静时段按 IANA 时区解释，使用 tzdata 保证 Windows 可用。跨午夜及夏令时
通过时区转换处理；设置变更在下一次检查及发布时生效。Inbox 显示来源、原因、时间、状态与失败，
自动内容清楚标记为提醒或草稿，不显示为用户发起的消息。

## Consequences

本地提醒可核验去重，模型费用有明确上限。暂停服务不会漏掉业务事实，也不会在重启时重做未知
副作用。代价是未知结果需要用户检查，安静时段开始时完成的草稿可被丢弃，已预留预算不保证产出。
不承诺外部副作用 exactly-once，不承诺服务未运行期间的准点提醒。

## Alternatives Considered

1. 使用进程内定时器直接弹通知：重启后丢失身份，难以防重复和核对，因此不采用。
2. 所有提醒都调用模型：普通时间规则不需要模型，且会混淆费用授权，因此分开生成与预算。
3. 在重启后重放所有任务：可能重做未知模型或副作用，因此只补查近期来源并保留未知终态。
