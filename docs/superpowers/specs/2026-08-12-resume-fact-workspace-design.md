# 简历事实补充工作台设计

状态：已批准实施

## 背景

OfferPilot 已有只读的“简历事实体检”和只读的版本差异审阅，但体检发现问题后，用户仍需自行定位 JSON、复制版本、编辑并重新打开对比。首期把这段断点收成一条可理解的路径：

`发现可补充事实 → 核对原文 → 用户写入并确认真实表述 → 创建派生版本 → 自动查看差异`

## 范围与边界

- 入口位于现有简历编辑页的“简历事实体检”，不增加顶层导航，不改变现有页面布局。
- 只处理已有字符串叶子的 `review` finding；结构缺失、未知结构和版式边界仍回到原编辑器处理。
- 系统只提供追问提示，不生成、不估算、不拼接数字或成果。最终写入内容必须由用户亲自输入，并勾选真实性确认。
- 原简历不修改。使用现有复制与更新接口创建派生版本，完成后自动打开现有版本差异审阅。
- 不新增 API、数据库、AI 调用、Pilot 工具或服务端状态。

## 确定性规则

新增纯函数模块负责：

- 判定 finding 是否可进入补充工作台；
- 严格解析 RFC 6901 JSON Pointer；
- 只允许替换与 finding 摘录逐字一致的字符串叶子；
- 拒绝非法转义、数组索引别名、危险属性、异常容器、超深或超大结构；
- 返回新对象，不修改原始 `content_json`；
- 最终表述按 Unicode code point 校验为 2–400 个字符。

## 交互

可补充 finding 展开后显示“补充真实事实”。工作台展示：

- 当前表述与字段路径；
- 三个核对提示：实际行动、可核验范围/数字、可验证结果；
- 用户填写的最终简历表述；
- “以上内容是本人确认的真实事实”复选框；
- “创建新版本并查看差异”主操作。

操作先复制原简历，再把确认表述写入复制版本。复制成功后立即把已知副本同步到本地列表。若更新请求的结果未知，不把它当作确定失败，也不允许用响应前的旧对象继续编辑；界面冻结操作、刷新列表并提示返回简历库核对。若复制结果未知，同样不按标题或父版本猜测结果，立即冻结操作、刷新列表，并提示返回简历库核对。

工作台只基于已保存简历运行；编辑器存在未保存草稿时，阻止发起补充并提示先保存或取消，避免创建新版本时丢失本地草稿。审计面板可显示 160 code point 预览，但精确替换必须使用同一 finding 内部保存的完整字符串做 CAS。

成功后更新本地简历列表、关闭编辑页，并以新版本为目标、父版本为默认基准打开现有版本差异 Drawer。

## 视觉与可访问性

- 复用当前控制级视觉语言：浅色表面、紫色主操作、清晰边框和状态标签。
- 工作台采用宽屏双栏（来源/编辑），窄屏单栏；不改变简历库和编辑器的结构。
- 对话层具备可访问名称、打开后焦点进入、Tab 循环、Escape 关闭和焦点恢复。
- 加载、失败、结果未知均使用文字说明，不能只依赖颜色。

## 测试与验收

- 纯函数：合法替换、无突变、Pointer 转义、数组索引、摘录漂移、危险键、异常容器、深度/节点预算、Unicode 长度。
- 组件：仅可操作 finding 显示入口；未确认、空白和超长文本不可提交；成功创建派生版本；更新失败重试不重复复制；结果未知冻结。
- 真实挂载：完成体检到版本对比，断言无 AI、Pilot、导航或其他领域写入。
- 浏览器：亮色中文宽屏，使用“筱哲”案例，截图至少覆盖事实补充工作台与生成后的版本差异。
