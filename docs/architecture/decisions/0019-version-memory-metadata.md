# ADR-0019：版本化个人记忆分类与显式有效期

- Status: Proposed（实现已落地，局部验证及独立审查通过；全量与真实浏览器验收中，不代表可发布）
- 日期：2026-11-16
- Decider：用户已同意的记忆路线，分类与时效阶段；本次不包含合并或发布授权
- 依据：[Knowledge 架构](../knowledge-system.md)、[可选上下文](0011-bound-optional-context-sources.md)

## Context

基线 `08d5bc85` 的确认记忆仅保存正文与确认时间。画像按关键词临时分组，召回却把所有正文
投影为 `preference`。分类、时间适用性、来源可信程度是三个不同维度，不能互相推导。
确认时间不证明记忆何时失效，用户确认也不证明外部事实或模型结论。

既有 mutation 指纹由完整请求默认值生成；直接添加默认字段会破坏升级前重放。
备份按完整 sqlite_master 比较结构，而且安装阶段再次核验结构和文件摘要，普通增加列会
使升级前备份被拒绝。兼容必须显式设计，不能通过忽略表、约束或触发器来放宽安全校验。

## Decision

### 版本、类型和证据

- 保留原记忆、版本及 mutation 表，新增以确认版本为外键的一对一元数据表。
- 分类为 `unclassified/preference/goal/experience/skill/preparation`，由用户显式选择。
  它是个人记忆用途，不是知识事实或能力评估结论。不把页面关键词分组自动写入。
- 期限 `valid_until` 允许为空；输入必须含时区，保存为 UTC。到期边界为 `now >= valid_until`。
  空值表示未指定，不声称永久有效。旧版本缺元数据行同样解释为未分类、未指定期限。
- `evidence_status=user_confirmed` 由服务端固定产生，不接受客户端伪造外部已核验状态。
  本轮不新增模型推断记忆、自动归档、自动确认、Knowledge Evidence 或来源对话链接。
- 到期只是读取时派生状态，不自动撤回、删除或产生新版本；仍可查看历史和显式重新确认。
  后续召回排除到期项；未指定期限仍可召回，但必须带期限未知语义。

### 写入和重放

- metadata 随正文一起确认和版本化；CAS 与单事务写入不变。
- 请求省略 metadata 时，新建采用保守默认，编辑继承最近确认版本；显式对象才更新分类及期限。
  这样旧客户端不会在编辑正文时悄悄丢失新元数据。撤回/删除拒绝 metadata。
- 旧请求哈希保留原字段及原默认展开规则，仅当请求明确包含 metadata 时才加入该对象。
  不能全局使用 exclude_unset。先核验已有 mutation 指纹，再读取或继承当前元数据。
- 删除同时清空全部版本正文和元数据；旧重放仍不可恢复删除内容。元数据本身也属于个人信息。

### 召回与显示

- 投影统一使用 `content/category/valid_until/evidence_status`，不再统一命名为 preference。
- 提示契约保留历史数据、当前请求优先、非指令/工具结果/操作授权边界，并说明个人陈述
  只作个性化、排序和表达参考，不能证明外部事实、业务发生或胜任程度。
- 画像提供显式分类与本地日期时间输入，显示期限、到期状态和个人确认来源；旧记录显示未分类。
  保留撤回、删除、版本、取消不写入和不确定响应重试。重试身份包括分类及期限。
- 本轮不做场景排序、向量索引、模型自动抽取、批量改写或真正可追溯分层整理。

### 备份兼容

1. 原 ZIP 的路径、安全、manifest 和文件摘要先按既有流程验证，原文件不修改。
2. 只允许当前完整 schema，或与当前 schema 恰好仅差本轮新增表的上一版 schema。
   任意其他历史结构、额外表/索引/触发器均保持拒绝，不把历史版本号当真实性证明。
3. 上一版在私有 stage 先通过原结构的完整性、外键、附件和 ledger key 校验，再执行固定受信
   DDL；不得调用含 reset 的 init_database，也不对用户当前工作区做试探迁移。
4. stage 迁移后重新校验当前精确 schema、完整性和附件；重新生成暂存 manifest 与文件摘要，
   保留原 ZIP 摘要及受限迁移标记。安装和重启仍核验 stage 没有被改动。
5. 失败只清理本次 stage；当前工作区及原归档字节不变。恢复仍要求用户的替换工作区确认。

## Consequences

小型 side table 保留历史语义并让上一版结构的受限识别可审计。代价是读取多一次关联，且分类
需要用户显式维护。到期不会触发持久写入，界面刷新和下一次模型投影时体现最新时间状态。
备份支持仅限本次已识别的前一结构，不承诺任意旧版本导入；不允许拿兼容为理由关闭严格校验。
旧程序不理解新期限，代码降级不保证继续执行到期排除；不能把保留数据或恢复成功等同于旧程序
支持新语义。恢复失败回滚针对本轮同版本安装流程，不是跨版本语义兼容承诺。

## Alternatives Considered

1. 继续关键词分类并给近期准备统一 TTL：无法区分用户实际意图，也会凭确认时间抹去仍有效记忆。
2. 在原正文嵌 JSON 或标签：污染用户内容、破坏旧消费者，无法清晰版本化及审计。
3. 直接给版本表加列并忽略备份 schema 差异：容易打断旧备份或放过危险结构。独立表使差异闭合。
4. 引入向量库/通用记忆框架或模型自动抽取：当前只有有界确认记录，增加基础设施并不能解决
   用户确认、有效期及事实证据边界；场景检索留下一阶段。

## Verification

实现必须证明：升级前真实指纹重放；CAS 不产生孤立元数据；元数据变化与重试身份；旧客户端
继承；无时区/数字时间戳拒绝；UTC 到期边界；未知期限仍召回；最终投影不再冒充偏好/事实；
撤回、删除、到期不泄漏；新备份往返、上一版受限迁移后冷安装、stage 篡改/恶意结构拒绝、
失败不改变原工作区。模型质量未验证时不得用契约测试代替真实模型质量结论。
