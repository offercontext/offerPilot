# Dashboard 与面试行动卡视觉设计

**状态：已确认**
**基线：`feat/20260813-live2d-pilot-mascot@f565e13`**

## 目标

在不改变现有页面布局、数据读取和业务语义的前提下，将工作台的本周指标与面试页的下一项训练统一为更清晰的行动卡：先给结论，再给进度或来源，最后提供现有入口。

## 本周关键事项卡

- 复用 `deriveMissionControl()` 已加载的六项 `MissionMetric`，不新增请求。
- 六项指标并非同一完成度量尺，因此只汇总阻塞项与需关注项，不生成百分比。
- 顶部显示“本周求职进度”和确定性的状态摘要，配非数值的渐变节奏线。
- 每行保留真实指标名称和值；值继续沿用现有 `current/target` 规则，状态文字继续沿用现有四态。
- 整卡与每一行均为只读派生；行点击只调用现有导航回调。

## 下一项行动卡

- 复用现有 `AdaptivePracticeRecommendation`，不新增 AI、API 或写入。
- 以“下一项行动”为 eyebrow，标题使用推荐标题，正文使用已保存复盘中的 observation。
- 固定展示三条边界说明：“来自已保存复盘”“适合一次短时训练”“不会自动写入故事库”，不虚构精确时长。
- 主按钮继续调用现有 `onOpenAdaptivePractice({ proposalId, focusId })`；加载失败和无推荐行为保持不变。

## 视觉与可访问性

- 保持 Dashboard、面试页和 Pilot 三栏布局不变。
- 使用低饱和紫蓝渐变、柔和光晕、白色半透明标签与细边框；不使用大面积高饱和色。
- 标题使用平衡换行，正文使用自然换行；窄屏改为纵向排列。
- 所有可点击行和按钮命中区域不小于 40px，具备可见焦点；减少动态效果时关闭位移动画。
- 深色模式沿用主题变量，确保文字与边框对比度。

## 测试与验收

- 纯函数覆盖空指标、四种状态与稳定状态摘要。
- 组件覆盖非数值状态摘要、未知数据、真实行值、行导航、行动卡边界标签及点击参数。
- 真实浏览器使用中文、亮色、宽屏验收，并保存工作台与面试页截图。
- 验证期间不得产生新增业务写入或外部浏览器请求。
