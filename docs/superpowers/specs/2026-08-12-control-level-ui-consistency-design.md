# OfferPilot 控件级 UI 一致性设计

状态：已确认，进入实施

## 1. 背景

OfferPilot 的核心求职链路已经具备完整功能，但部分页面仍直接堆叠 Ant Design 的默认表单、列表、标签与操作按钮。此前已优化工作台、简历、材料、Offer、谈薪、故事库和岗位资料历史中的部分界面，因此当前主要问题不是缺少视觉风格，而是不同模块对同一种状态和操作采用了不同的控件表达。

本次只做控件级与内容层级收口，不改变页面信息架构、导航、业务流程、API、数据库、AI 契约或持久化语义。

## 2. 设计目标

1. 同类操作在不同模块中具有一致的尺寸、主次、状态和反馈。
2. 长文本、来源、证据、历史和异常状态可以稳定扫读，不溢出、不依赖标签堆叠。
3. 宽屏充分利用现有容器，窄屏只改变排列，不改变语义或操作顺序。
4. 已优化页面继续复用现有品牌变量，不引入第二套视觉体系。
5. 所有修改保持当前业务行为和请求边界不变。

## 3. 视觉语言

### 3.1 控件尺寸与焦点

- 普通按钮、输入框、选择器和数字输入框保持 `36px` 基础高度。
- 关键表单和主要提交操作可使用 `40px`，但同一操作组不得混用高度。
- 圆角使用现有 `--op-control-radius`，内容卡片使用 `12px`，Drawer 内分组使用 `10–12px`。
- 键盘焦点统一使用 `--op-focus-ring`，不得仅通过颜色变化表达焦点。
- 禁用状态必须同时降低视觉权重并保持文本可读。

### 3.2 操作层级

- 每个局部区域最多一个高亮主操作。
- 次要操作使用普通按钮或文字按钮；危险操作使用克制的红色边框/文字，不与主操作争夺注意力。
- 操作组保持稳定间距，窄屏允许换行但不得改变操作顺序。
- 结果未知、生成中和来源冲突时，只显示安全恢复动作，禁止视觉上仍像普通可编辑状态。

### 3.3 表单

- 标签、输入、帮助文本和错误提示形成稳定的垂直节奏。
- 长文本输入和历史文本统一允许换行，并使用 `overflow-wrap: anywhere` 防止 URL、JSON Pointer、英文技术栈或无空格文本溢出。
- 复杂表单使用浅色分组面板表达阶段，不增加无意义的多层 Card。
- 成功、错误、只读和未知结果状态使用统一的内联状态面板。

### 3.4 列表、历史与详情

- 列表行按“标题 → 摘要 → 状态/来源 → 操作”组织。
- 当前、冻结、变化、缺失和只读状态使用现有 `SourceStateTag` 或语义一致的状态标签。
- 新增/编辑/归档等操作保持固定位置；历史内容与当前草稿视觉隔离。
- 证据内容使用结构化行或可展开区块，不能把长引用拆成大量胶囊标签。

### 3.5 Drawer、Modal 与空状态

- Drawer/Modal 统一标题、说明、内容分组和底部操作区。
- 长内容区域独立滚动，关闭与主操作保持可达。
- 空状态必须说明“为何为空”以及安全的下一步；没有下一步时明确为只读信息。
- Escape、Tab 循环、可访问名称和焦点恢复沿用现有可访问性边界。

## 4. 模块范围

### 4.1 第一批：面试与评估核心链路

- `InterviewV01View`：面试入口、日程列表、复盘与准备入口、空状态。
- `MockInterviewDrawer`：阶段标题、回答区、反馈、历史、异常与重试操作。
- `InterviewPreparationProposalDrawer`：来源说明、建议分组、选择与确认区。
- `InterviewKnowledgeCaptureDrawer`：来源选择、摘录、知识草稿与状态提示。
- `OpportunityFitReviewDrawer`：Triage、Deep Review、来源风险、历史与操作区。
- `ResumeMatchModal`：简历选择、匹配结果、证据和加载/错误状态。

### 4.2 第二批：工具与系统页面

- `ScheduleEventForm`：日期、时间、类型和备注的表单层级。
- `AISettingsDrawer`：Provider 列表、连接配置、编辑与验证状态。
- `ActionDetailDrawer`：行动详情、来源、时间与状态。
- `CommandPalette`：搜索、分组、选中态和快捷键提示。

### 4.3 一致性复核

- `KnowledgeSourcesView`、`QuestionBankView`、`ApplicationDetail`、Pilot 卡片及已优化页面只修复明确的控件脱节、溢出或状态不一致；不进行结构重排。
- Dashboard、简历版本、材料包、Offer、谈薪和故事库保留现有布局，只复核与新增公共类的兼容性。

## 5. 实现策略

1. 在 `web/src/theme/tokens.css` 增加小型、语义明确的公共控件类：内容面板、区块标题、工具栏、列表行、内联状态、空状态和自动换行。
2. 公共类只负责视觉与响应式，不包含业务状态推断。
3. 各组件保留现有 props、回调、service 调用、请求顺序和条件分支，只替换布局容器与类名。
4. 复杂组件优先移除重复 inline style；组件特有细节可使用同名 CSS Module，避免继续扩大全局选择器。
5. 不引入新依赖，不修改 Ant Design 主题算法，不重写现有页面布局。

## 6. 测试与验收

### 6.1 自动化测试

- 公共样式契约：控件高度、自动换行、状态面板、响应式操作组和深色变量均存在。
- 真实挂载测试：核心 Drawer/Modal 保留原有标题、按钮、禁用状态、回调与零额外请求边界。
- 回归测试：长 URL、JSON Pointer、中英文技术栈和长证据摘录不会产生不可换行容器。
- 运行前端全量测试、TypeScript 和生产构建。

### 6.2 浏览器验收

- 使用实际配置的隔离部署、中文案例、亮色模式和不低于 `1440×900` 的宽屏。
- 至少覆盖：面试索引、模拟面试、岗位评估/面试准备、设置或日程中的一个工具页。
- 检查控制台错误、横向溢出、长文本、主次操作、空状态、Drawer 滚动和窄栏适配。
- 输出优化后的截图并逐张回读；截图不得包含密钥或 Provider 原始响应。

## 7. 明确不做

- 不新增或删除功能入口。
- 不改变页面布局、导航层级和 Pilot 宽度。
- 不修改 API、数据库、后端、AI Prompt、证据契约或业务重试语义。
- 不添加动画装饰、渐变背景堆叠、玻璃拟态或与现有产品不一致的视觉风格。
- 不把标签数量增加作为“优化”。

## 8. 完成标准

1. 第一、二批组件完成控件级收口，一致性复核未发现明显脱节。
2. 前端全量测试、TypeScript、生产构建和 `git diff --check` 通过。
3. 中文亮色宽屏浏览器走查无控制台错误或横向溢出。
4. 截图能够清晰展示面试、评估和工具页的统一控件语言。
5. 工作区干净，变更仅位于前端、测试和本次设计/计划/验收文档。
