# Mock Interview 复盘生成与可见反馈修复设计

日期：2026-08-16

状态：已由用户批准修复方向，待书面复审

## 背景与已确认根因

快速练习 Attempt 11 点击“结束并生成复盘”后，后端确实收到请求。真实 Provider 调用约 39.7 秒后返回了一个包含空白必填值的反馈对象，严格验证器将其分类为 `blank_value`，API 返回 `502 mock_interview_unverifiable`。

界面同时存在两个可见性问题：请求期间按钮仅被禁用，没有持续展示“正在生成复盘”；终态错误提示被插入对话滚动区顶部，而用户停留在底部，因此请求执行和失败结果都像“没有反应”。

## 目标行为

- 点击结束后立即在当前视口显示“正在生成复盘”，按钮进入 loading 状态并禁止重复提交。
- 生成中提示说明真实 Provider 可能需要几十秒，但不显示虚构进度或倒计时。
- 成功后展示复盘卡片；结果未知继续保留原 feedback key；终态契约失败明确提示必须重新开始。
- 开始错误、结果未知和终态失败统一显示在 Studio 顶部、对话滚动区之外，并在状态变化后获得程序化焦点。
- `blank_value` 允许一次受限格式修复；仍失败时保持现有终态语义。
- 不改公开 API、数据库、证据目录、幂等键、lease/CAS/fencing 或人工确认边界。

## 后端受限修复

将 `blank_value` 纳入现有 `_FORMAT_REPAIR_CATEGORIES`。它只允许同一生成操作额外调用 Provider 一次，沿用原冻结快照、完整证据目录和原始回答，不改变输入事实。

修复提示继续要求：

- 只返回声明的 JSON Schema；
- 文本和摘录不得为空；
- 证据摘录必须逐字来自允许的冻结值；
- 不得通过删掉必需证据、编造文本或放宽验证器来通过。

首次与修复输出均经过同一个严格验证器。若第二次仍为 `blank_value` 或出现任何语义/证据错误，Attempt 仍进入 `contract_failed`，API 仍返回 `502 mock_interview_unverifiable`。

## 前端反馈区

Studio 顶部工具栏下新增一个不参与对话滚动的状态区：

- `feedback_submitting`：信息提示“正在生成复盘，通常需要几十秒，请勿重复点击”。
- `result_unknown`：警告提示并提供“使用原 key 重试”。
- `contract_failed`：警告提示并提供“重新开始练习”。
- `startError`：保留原 key 恢复入口。

这些状态只显示一份，原对话滚动区中的重复 Alert 删除。错误或未知状态出现时，状态区通过 `tabIndex=-1` 和受控聚焦让键盘及读屏用户立即感知；不抢占生成中状态的焦点。

“结束并生成复盘”按钮仅在 feedback 操作期间显示 loading 与“正在生成复盘…”，其他请求仍按现有 working/phase 规则禁用，不把问题生成或回答提交误标为复盘生成。

## 数据与恢复语义

- 当前 Attempt 11 已是终态失败，修复不会回写或伪造其复盘结果。
- 新 Attempt 从新规则开始生效。
- Provider/网络未知仍冻结输入并保留 feedback key；用户显式点击后才使用原 key 恢复。
- 终态失败不复用旧 Attempt 自动重试，必须由用户点击“重新开始练习”。

## 测试与验收

- AI：首次 `blank_value`、第二次合法时成功且调用两次；连续两次 `blank_value` 时终态失败且调用次数固定为二。
- API：修复成功返回既有 proposal 响应；修复失败仍返回稳定 `mock_interview_unverifiable`。
- 前端：点击结束后立即显示 loading 和当前视口状态；终态错误/结果未知位于滚动区外；错误状态获得焦点；重复点击不产生第二个请求。
- 回归：现有结果未知原 key、重新开始、连续语音、问题生成、证据验证保持通过。
- 真实验收：只执行一次有界 real-AI Mock Interview 验收，不为制造通过而重复调用 Provider。

## 非目标

- 不降低证据或语义验证强度。
- 不增加无限重试、自动后台重试或新的进度百分比。
- 不修改历史 Attempt、公开 API 或数据库结构。
- 不在本修复中优化复盘内容样式或新增复盘指标。
