# Interview Studio 对话式双栏工作台设计

- 状态：已复审通过
- 日期：2026-08-16
- 设计基线：`6015a16468fc38eb07446f2eded8e596759249c3`
- 分支：`feat/20260815-continuous-voice-interview`
- 范围：只重组 Interview Studio 的信息架构与视觉布局，不改变面试状态机、API、证据、语音、幂等或持久化语义

## 1. 背景与问题

当前 Studio 将当前问题、证据、语音整理、转写确认和表达复盘纵向堆叠。长问题和完整证据会占据上半屏，用户需要在“面试对话”和“回答处理”之间来回滚动；连续语音模式下，转写与确认按钮还可能落到视口外。它虽然包含完整能力，但不符合用户对面试的核心心智模型：左边是持续推进的对话，右边是当前回答的控制台。

本次采用用户已确认的左右双栏方案，将“对话上下文”和“当前回答任务”分离，同时保持二者在同一视口内可见。

## 2. 方案选择

### 2.1 采用：64 / 36 对话与回答双栏

- 左侧约 64% 为唯一的面试对话时间线，承载历史问题、已确认回答、当前问题和简要提问依据。
- 右侧约 36% 为当前回答工作台，承载模式状态、录音/回放、转写核对、表达节奏复盘和提交动作。
- 右侧以“回答 / 依据”页签复用空间；证据不再永久占据第三栏。
- 两栏独立内部滚动，页面本身保持固定视口，不再让回答控件随长对话下沉。

这一方案直接对应用户已批准的视觉预览，并与现有 Interview Studio 的业务职责一致。

### 2.2 不采用：继续纵向堆叠

只调整字号、间距或卡片高度无法解决用户在长问题、长转写和证据之间反复滚动的问题。

### 2.3 不采用：永久三栏

“对话 / 证据 / 回答”三栏会压缩回答区，在 1280px 和较长中文内容下重新产生拥挤与溢出。证据属于当前任务的辅助信息，应通过右侧页签按需查看。

## 3. 宽屏结构

`min-width: 1180px` 时使用双栏：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：退出、场景标题、轮次、来源冻结、Haru、结束             │
├──────────────────────────────────┬───────────────────────────┤
│ 面试对话 64%                     │ 回答 / 依据 36%           │
│                                  │                           │
│ 面试官问题                       │ 连续语音与录音状态        │
│                    用户确认回答  │ 音频回放                  │
│ 面试官追问                       │ 转写核对                  │
│                    用户确认回答  │ 表达节奏复盘              │
│ 当前问题 + 简要证据标签          │                           │
│                                  │ [重录] [确认并提交回答]   │
└──────────────────────────────────┴───────────────────────────┘
```

- Studio 顶栏继续是全宽固定区域，保留现有状态和退出语义。
- 主体使用 `minmax(0, 1.75fr) minmax(360px, 1fr)`，列间距 20–24px。
- 主体高度为视口减去顶栏和安全间距；两栏均设置 `min-height: 0`，只在各自内容区滚动。
- 不在双栏下方继续渲染另一套语音或复盘卡片。

## 4. 左侧面试对话

### 4.1 时间线语义

- 面试官消息左对齐，使用克制的中性卡片，显示“面试官”、时间或轮次。
- 用户已确认回答右对齐，使用轻微紫色底，不把未确认转写显示成历史回答。
- 历史 Turn 按服务端确认顺序稳定展示；本次布局不改变最多五轮、追问关联或历史只读规则。
- 当前问题仍是唯一主要标题，但采用正常对话字号，不再使用会挤压视口的超大排版。

### 4.2 当前问题与证据提示

- 当前问题位于时间线末尾，并保留可聚焦标题用于题目切换后的键盘定位。
- 问题卡内只显示简短“提问依据”标签和来源 chip，例如“冻结 JD”“冻结简历”。
- 点击证据 chip 将右栏切换到“依据”页签并定位对应证据；不新建页面、不改变来源冻结状态。
- 完整 excerpt、JSON Pointer 和高亮仍由现有证据组件展示，不能把截断标签当成完整证据。

### 4.3 Haru

- Haru 默认停靠在对话栏安全边缘，不遮挡消息、滚动条或当前问题。
- 继续支持拖动、隐藏、缩放和位置记忆；拖动边界依据新的双栏安全区重算。
- 空闲状态只显示 `Haru · Pilot` 名牌，不持续显示“随时待命”气泡。

## 5. 右侧回答工作台

### 5.1 页签

- “回答”为默认页签，容纳当前轮所有可操作内容。
- “依据”复用现有冻结来源、完整 excerpt、路径、高亮和折叠逻辑。
- 页签切换只影响本地展示，不重建 Attempt、不清理转写、不触发 API。
- 新问题到达时默认回到“回答”；用户通过证据 chip 主动进入“依据”时保持明确焦点。

### 5.2 回答页

从上到下固定为：

1. 标准文字 / 语音 / 连续语音模式及当前可观察状态；
2. 录音、暂停、继续、停止、回放或降级入口；
3. “核对回答文字”编辑区；
4. 本地“表达节奏复盘”摘要；
5. sticky 操作栏。

右栏内容区可以内部滚动，但底部操作栏始终可见。操作栏只展示当前状态允许的动作，例如“重录”“继续补充”“确认并提交回答”；禁用状态必须同时给出可感知原因。

### 5.3 人工确认与恢复

- 只有用户点击“确认并提交回答”后，文字才进入既有回答 API。
- 录音、临时字幕、未确认文字和本地复盘继续遵守现有本地边界。
- 202、网络未知、Provider 未知、原 key 恢复、下一题生成和 Voice Coaching 保存语义均不改变。
- 结果未知期间右栏冻结会改变输入的控件，但仍显示当前文字和恢复状态。

## 6. 窄屏与响应式

- `< 1180px` 时不强行保留左右双栏。
- 对话成为全屏主区域；回答工作台以底部 Drawer 打开，入口固定在当前问题附近或底部安全区。
- Drawer 使用单一内部滚动和固定提交栏，打开时管理焦点、`inert` 背景并锁定页面滚动。
- “依据”继续作为 Drawer 内页签，不另开覆盖层。
- `390×844` 下 Haru、输入区、键盘安全区和提交按钮不得互相遮挡；横向溢出必须为零。

## 7. 视觉与交互规则

- 延续 OfferPilot 现有亮暗色 token，不引入新的品牌色或大面积紫色渐变。
- 卡片层级主要依靠背景明度、轻边框和克制阴影，不用多层厚边框。
- 交互命中区域不小于 40px；计时与指标使用 tabular numerals。
- 所有滚动容器必须有清晰的键盘访问路径，不能形成不可退出的嵌套滚动陷阱。
- `prefers-reduced-motion` 下移除装饰动画，不影响录音状态和焦点反馈。
- 亮色、暗色、125% 缩放和 Windows 中文字体下不得出现文本重叠或裁切。

## 8. 组件边界

优先在现有 feature 内拆分展示职责，业务状态继续由 `InterviewStudio` 持有：

```text
web/src/features/interviewStudio/InterviewStudio.tsx
web/src/features/interviewStudio/InterviewStudio.module.css
web/src/features/interviewStudio/InterviewConversationPane.tsx
web/src/features/interviewStudio/InterviewAnswerWorkspace.tsx
web/src/features/interviewStudio/InterviewEvidencePane.tsx
```

- `InterviewConversationPane` 只渲染 timeline、当前问题和证据入口。
- `InterviewAnswerWorkspace` 组合现有 `ContinuousVoiceModePanel` 与 `VoiceAnswerComposer`，接收已存在的命令和回调，不复制媒体状态机。
- `InterviewEvidencePane` 从当前证据数据派生展示，不请求或持久化来源。
- `InterviewStudio` 继续负责 Attempt、Turn、回答提交、下一题、结果未知、退出确认和焦点陷阱。

若现有组件已能以 props 完成上述职责，可保留原文件；不得为了视觉重构复制第二套请求、录音或证据逻辑。

## 9. 测试与验收

### 9.1 组件与布局测试

- 宽屏渲染两栏且只有对话栏与回答栏两个主区域。
- timeline 的面试官/用户对齐和顺序稳定，未确认转写不进入历史。
- 证据 chip 切换右栏“依据”并定位来源；切回“回答”不丢失文字或音频状态。
- 长问题、长转写、五轮历史分别只让目标区域滚动，提交栏仍可见。
- 标准文字、手动语音、连续语音、降级、结果未知和完成态均映射到正确操作。
- 窄屏使用底部 Drawer，焦点进入、Tab 循环、Escape 关闭和焦点恢复正确。
- Haru 在宽屏和窄屏均不与当前问题、工作区按钮或滚动条重叠。

### 9.2 业务零回归

- 布局切换、页签和滚动不产生新请求、Provider 调用或写入。
- 已确认回答只提交一次，后续追问使用原有 evidence refs。
- 语音资源、连续模式 generation fencing、人工确认和原 key 恢复测试继续通过。
- 快速练习仍不写入 Application、Event、Knowledge、Memory、Story 或 Offer。

### 9.3 浏览器验收

使用中文隔离样例完成：

```text
进入快速练习
→ 查看历史对话与当前问题
→ 从问题 chip 打开依据并高亮来源
→ 回到回答页录音、转写、编辑
→ 查看表达节奏复盘
→ 确认提交并生成追问
→ 完成五轮与退出恢复
```

至少保留以下证据：

- `1440×900` 亮色双栏完整视图；
- `1440×900` 依据页签及高亮；
- `1440×900` 连续语音转写确认；
- `390×844` 对话主界面；
- `390×844` 回答 Drawer 与固定提交栏；
- 暗色和 125% 缩放无重叠检查。

截图必须使用同一轮真实挂载状态，回读确认没有文本重叠、裁切、横向溢出或 Haru 遮挡。

## 10. 破坏性变化与风险

预期没有 API、数据库、类型或持久化破坏性变化。主要风险是把现有大型 `InterviewStudio` 拆分时误改请求生命周期，以及双内部滚动造成键盘陷阱。控制方式是先为既有业务行为补挂载回归，再仅移动展示结构；每个新子组件只接收数据和回调，禁止直接调用 service。

## 11. 完成条件

- 宽屏与批准预览一致：左侧对话、右侧回答/依据工作台、固定提交区。
- 窄屏保持单一主滚动，回答 Drawer 不遮挡当前问题和 Haru。
- 长对话、长证据、长转写均无页面级下沉、文本重叠或横向溢出。
- 现有连续语音、语音复盘、证据链、人工确认、幂等与恢复测试无回归。
- 定向测试、前端完整门禁、TypeScript、生产构建、Smoke、真实浏览器验收和独立 CR 全部通过后才可提交合并审核。
